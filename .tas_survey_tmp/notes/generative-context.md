# Generative / long-context TAS methods — evidence notes

Project context these notes are written for: per-frame **144-dim** hand-crafted features (YOLO over a 2×3 ROI grid: per (class, region) [presence, count, max_area]), tiny dataset (~2,639 test frames / 8 videos, ~9 classes + idle), **segment-level** business metric (edit, F1@k, insertion recall, frame acc), best current model MS-TCN++ (4×10, hidden 128, ~3.3M params) → edit 51.08, F1@0.1 40.01, frame acc 53.98. Dominant failure: 51.6% of GT segments get a wholly wrong label.

### Diffusion Action Segmentation (DiffAct)
- **Venue/year**: ICCV 2023. Verified twice: arXiv `Comments:` field on https://arxiv.org/abs/2303.17959 literally says `ICCV 2023`; and the CVF page metadata (`citation_conference_title = Proceedings of the IEEE/CVF International Conference on Computer Vision`, pages 10139–10149) at https://openaccess.thecvf.com/content/ICCV2023/html/Liu_Diffusion_Action_Segmentation_ICCV_2023_paper.html
- **URL**: https://arxiv.org/abs/2303.17959 (v1 31 Mar 2023, v2 12 Aug 2023; full text used: https://arxiv.org/html/2303.17959)
- **Code**: https://github.com/Finspire13/DiffAct (reached by resolving the paper's own link `tinyurl.com/DiffAct`) — **MIT License** (checked `api.github.com/repos/Finspire13/DiffAct` license=MIT **and** the LICENSE file body "MIT License Copyright (c) 2023 Daochang Liu"). Repo description: "Code for Diffusion Action Segmentation (ICCV 2023)", last push 2023-08-16.
- **Core mechanism**: TAS is cast as **conditional generation of the action-label sequence**. At training, Gaussian noise is added to the **one-hot ground-truth label sequence** `Y0 ∈ {0,1}^{L×C}` to give `Ys = sqrt(ā_s)·Y0 + ε·sqrt(1-ā_s)` (Eq. 4); a step-aware decoder `Ps = g_ψ(Ys, s, E⊙M)` (Eq. 5) denoises it, where `E = h_φ(F)` is an ASFormer-encoder re-implementation of the 2048-d I3D features and `M` is the masking vector. At inference the decoder starts from **pure noise** `Ŷ_S ~ N(0,I)` and iterates Eq. 9 (itself a re-implemented ASFormer decoder with an added **step embedding**), with skipped steps (`S=1000` training steps, `25` inference steps). Losses: per-frame cross-entropy + temporal smoothness (log-likelihood MSE between adjacent frames) + **boundary alignment loss** (BCE between `1 - Ps,i·Ps,i+1` and a Gaussian-smoothed GT boundary `B̄`). So: **the diffusion process operates on the label sequence (frames × classes), not on frames/features**; the visual features enter only as conditioning.
- **"Unified masking strategy" — exactly what it does**: a per-frame binary mask `M ∈ {0,1}^L` multiplied element-wise onto the conditioning features `E` before the decoder, sampled at each training step from four types:
  - `M^N` = all-ones (**no masking**; fully conditional).
  - `M^P` = all-zeros (**position prior**; unconditional — timestamp locations are all that is left, forcing the model to learn where actions occur in time; the paper notes the model still gets edit 34.8 with all features blocked, "much better than the random guess").
  - `M^B` = `1(B̄_i < 0.5)` (**boundary ambiguity**; drops features near GT boundaries, forcing use of context/duration of neighbouring actions instead of unreliable boundary frames).
  - `M^R` = `1(Y_{0,i,c̃} ≠ 1)` for a randomly chosen action class `c̃` (**relational dependency**; blanks out all frames of one random action class, forcing the model to infer the missing action from its surrounding actions).
  At inference **no masking is used** (`E` is fed unmasked).
- **Problem targeted**: multi-stage/iterative-refinement TAS is expensive and has no generative prior over action sequences; the paper injects label-sequence priors (where actions sit in time, ambiguous boundaries, which actions co-occur/co-follow) into a diffusion framework.
- **Datasets & metrics** (Table 1, method rows as printed in the paper; feature backbone for all: **pre-extracted I3D, D=2048**):
  - GTEA → F1@{10,25,50} **92.5 / 91.5 / 84.7**, Edit **89.6**, Acc **82.2** (Avg 88.1)
  - 50Salads → F1@{10,25,50} **90.1 / 89.2 / 83.7**, Edit **85.0**, Acc **88.9** (Avg 87.4)
  - Breakfast → F1@{10,25,50} **80.3 / 75.9 / 64.6**, Edit **78.4**, Acc **76.4** (Avg 75.1)
  - Metrics defined in §5.1: frame-wise accuracy (Acc), edit score (Edit), F1 at overlap thresholds 10/25/50%.
- **Params**: Table 7 (50Salads): DiffAct **0.975M params**; FLOPs **4.96G / 7.73G / 10.85G** at 8 / 16 / 25 inference steps; training memory 1.9G; inference time **0.68s / 1.30s / 2.09s**; Avg **86.6 / 87.1 / 87.4** vs backbone ASFormer 1.134M, 6.66G, 2.38s, Avg 81.9. (Cross-check: FACT's Table 4 measures DiffAct at 1.7M params / 63.0 GFLOP on a 5-min video, and BaFormer's Table 6/11 measures DiffAct-25-steps at 1.21M / 43.94G / 2.306s — different measurement setups; quote each with its source.) Training uses Adam, batch size 4, and fits "on a single NVIDIA RTX 2080 GPU" (supplementary).
- **Small-data & low-dim-feature relevance**:
  - *Low-dim features*: technically fine — the only place the input dimension is hard-coded is the I3D 2048-d `F` feeding `h_φ`; a 144-d linear projection is a drop-in. The encoder was 10/10/12 layers with 64/64/256 feature maps (GTEA/50Salads/Breakfast) and the decoder 8 layers with 24/24/128 maps, conditioning features `E` with `D'=768` (Breakfast) or `192` (others) built by concatenating encoder layers 5/7/9 — i.e. small versions already exist for the tiny GTEA dataset.
  - *Small data*: the paper's own stated limitation is that "its advantage on the small-scale dataset, GTEA, is not as significant as on large datasets" — a direct warning for a ~2.6k-frame dataset. Cost is the other risk: 1000 diffusion steps at training and 8–25 decoder passes at inference (25 steps ≈ 10.85 GFLOPs and 2.09s per video at their scale).
  - *Whole-segment identity*: this is the **only paper among these four that models the label sequence generatively**. Because `Y_s` is the (noisy) label sequence, the decoder can in principle enforce global label-sequence coherence (which actions can appear, in what order/position), which is exactly the failure mode (whole-segment wrong label). Note however that (a) all masking acts on the *feature* conditioning `E`, never on the label sequence, and (b) `M^R` (the relational prior that most directly targets "which action belongs here") can only be built from ground-truth labels at training time, and the paper's own inference-time experiment with `M^R`/`M^B` is explicitly labelled "only for analysis purposes since the mask types B and R depend on the ground truth".
- **Verification notes**: fetched arXiv abs (comments=ICCV 2023), arXiv HTML full text (method §4.1–4.2, implementation details §8, Tables 1/2/6/7/8), CVF ICCV page metadata, GitHub API + LICENSE for Finspire13/DiffAct. NOT verified: no independent measurement of its behaviour on low-dim features; the supplementary note about concatenated encoder layers 5/7/9 is from the main HTML text (§8).

### How Much Temporal Long-Term Context is Needed for Action Segmentation? (LTContext)
- **Venue/year**: ICCV 2023. Verified: arXiv `Comments:` field on https://arxiv.org/abs/2308.11358 says `ICCV 2023`. (v1 22 Aug 2023, v2 25 Sep 2023; no `Journal reference` field.)
- **URL**: https://arxiv.org/abs/2308.11358; full text used: https://arxiv.org/html/2308.11358 (also mirrored at https://ar5iv.labs.arxiv.org/html/2308.11358)
- **Code**: https://github.com/LTContext/LTContext — license **CC BY-NC 4.0 (Attribution-NonCommercial 4.0)**, read from the repo's LICENSE file ("Attribution-NonCommercial 4.0 International"); GitHub API license field = `NOASSERTION` (i.e. the file is non-standard for GitHub's detector, but it is a CC BY-NC text). **Non-commercial — relevant if this is an industrial deployment.** 50 stars, last push 2024-06-21.
- **Core mechanism**: a 4-stage transformer whose block alternates two attentions (Fig. 2/3):
  1. **Temporal Windowed Attention (WA)** — sequence split into non-overlapping windows of size `W` (W=64 in practice); attention computed `T/W` times, with an **overlap**: for each query window `Q ∈ R^{W×D}` the keys/values are the next window as well, `K,V ∈ R^{2W×D}` (masked when running past the end).
  2. **Temporal Long-Term Context (LTC) attention** — the sequence is partitioned into windows of size `G` and one element is taken per window, then attention is computed over **all** windows for each of the `G` offsets: `Q,K,V ∈ R^{(T/G)×D}`. `G` is the sparsity knob (`G=1` = full-sequence attention). Practice: `W=G=64` for 50Salads/Assembly101, `W=64, G=8` for Breakfast.
  Each block also has a 1D dilated temporal conv (kernel 3, doubling dilation, GELU) before the attentions; 4 stages × `N=9` layers (dilation resets each stage), a multi-stage loss (CE + MSE smoothing as in MS-TCN), and stages 2–4 use **cross-attention** with `Q,K` from the previous stage's frame-wise class probabilities `P` and `V` from features. A linear layer reduces features from 2048 → 64, and a further layer 64 → 32 "reduces the number of parameters from 1.42 million to 0.72 million without reducing the accuracy".
- **Problem targeted**: how much long-term context does TAS actually need? Prior hybrids (ASFormer etc.) attend only inside a local window. Their answer: **the full video context is necessary** for best performance — Fig. 4 shows the full sequence beats any window (even 50% of the video), Fig. 5 shows the gap between 50% window and 100% is *larger for long videos*, and a **video-specific** window is much worse than a fixed window.
- **Datasets & metrics** (Tables 1–2; features: **I3D (2048-d) for 50Salads and Breakfast, TSM (2048-d) for Assembly101**):
  - **Assembly101** (4,321 videos, 202 coarse classes, avg 24 segments/video, 7.1 min/video — the industrial toy-vehicle assembly dataset; evaluated on validation set per [46]) → F1@{10,25,50} **33.9 / 30.0 / 22.6**, Edit **30.4**, Acc **41.2**, **Params 0.72M**, inference **0.6 s** (Table 2). For scale: MS-TCN++ 31.6/27.8/20.6, Edit 30.7, Acc 37.1, 1.08M, 0.1s; C2F-TCN 33.3/29.0/21.3, Edit 32.4, 6.89M; ASFormer 33.4/29.2/21.4, Edit 30.5, 1.13M, 2.1s.
  - **50Salads** → F1@{10,25,50} **89.4 / 87.7 / 82.0**, Edit **83.2**, Acc **87.7** (Table 1, 5-fold average).
  - **Breakfast** → F1@{10,25,50} **77.6 / 72.6 / 60.1**, Edit **77.0**, Acc **74.2** (Table 1, 4-split average).
  - Training on Assembly101: "our approach requires 1 day and 18 hours" vs 4 weeks for ASFormer and 2 weeks for UVAST (both retrained by the authors). Epochs: Breakfast 150, Assembly101 120, 50Salads 200 (Adam, cosine decay; supplementary).
- **Params**: **0.72M** (Table 2; supplementary: 1.42M without the 64→32 linear reduction). Cross-paper measurement: BaFormer's Table 6 lists LTContext at 8.31 GFLOPs / 0.66M params / 0.202 s; FACT's Table 4 lists LTContext at 0.7M / 7.8 GFLOP.
- **Small-data & low-dim-feature relevance**:
  - Feature dimensionality is not architecturally fixed (a 2048→64→32 projection); a 144-d input is a drop-in. The main claim ("use the full video") is *favourable* for our setting: our videos are ~330 frames, so full-sequence attention is trivially affordable — `G=64` sparse attention would be pointless at that length (`G=1` = dense).
  - Small-data risk is structural, not contextual: 4 stages × 9 layers of attention over T frames with `W=64` windows at 2048→64 dims. They themselves note using 9 layers (not 10) because deeper overfits some datasets, and the whole paper's premise is that these datasets are "long videos" — nothing here says it works with ~2.6k test frames.
  - It says nothing about per-segment identity: the model is purely frame-wise (multi-stage TCN+attention), i.e. it targets the *boundary/localisation* side of the problem rather than our whole-segment label confusion.
- **"Is there a distinct 2025 LTContext paper?"** — **No primary source found for a distinct 2025 paper named LTContext.** What I checked: arXiv title search `LTContext` → **"no results."**; arXiv title search `long-term temporal context action segmentation` → exactly **1** hit, `2308.11358`; arXiv field search `all=LTContext` → **"no results."**. Web search for "LTContext 2025" surfaced only *later works that USE LTContext as a baseline* (e.g. a 2025 medRxiv clinical-cohort preprint reporting fine-tuning LTContext, and a Nature Parkinson's-disease paper comparing MS-TCN/ASFormer/LTContext) — **not** a new LTContext method paper. Note also arXiv metadata gives no journal reference for 2308.11358 (v2 is the last version, Sep 2023), and the GitHub repo's last push is 2024-06-21. → For item 3, LTContext = the ICCV 2023 paper, full stop. Any "2025 LTContext" claim should be treated as UNVERIFIED unless a primary source is produced.

### Efficient Temporal Action Segmentation via Boundary-aware Query Voting (BaFormer)
- **Venue/year**: **NeurIPS 2024** (main conference track). Verified from the official proceedings page: "Advances in Neural Information Processing Systems 37 (NeurIPS 2024) Main Conference Track" at https://proceedings.neurips.cc/paper_files/paper/2024/hash/42770daf4a3384b712ea9c36e9279998-Abstract-Conference.html (the arXiv `Comments:` field only says "17 pages, 8 figures, 11 tables", and there is no `Journal reference` field; the README's own badge links to the proceedings PDF).
- **URL**: https://arxiv.org/abs/2405.15995 (v1 only, 25 May 2024); full text used: https://arxiv.org/html/2405.15995; proceedings: https://proceedings.neurips.cc/paper_files/paper/2024/file/42770daf4a3384b712ea9c36e9279998-Paper-Conference.pdf
- **Code**: https://github.com/peiyao-w/BaFormer — **no license found**: repo root contents (via GitHub API) are `Inference.py, README.md, __init__.py, action_segmentation, configs, figures, main.py, requirements.txt` (no LICENSE), `raw.githubusercontent.com/.../main/LICENSE` → **HTTP 404**, GitHub API `license` = `null`, and the README contains no license section. 9 stars, last push 2025-11-05.
- **Core mechanism — "per-segment classification" + query voting**:
  - The dense part is a **frame-wise encoder–decoder**: frozen **I3D** encoder (C0=2048) → **ASFormer encoder as frame decoder** (11 layers, output dim 64), producing `F_d ∈ R^{T×C}` plus the per-layer features `{f_i}`.
  - A **Transformer decoder** (10 layers, 3 heads, hidden 128, initialized with **M trainable instance queries** `Q0 ∈ R^{M×C}`; M = **90 for GTEA, 100 for 50Salads/Breakfast**) converts the dense sequence into a **sparse set of segment instances**: each layer uses **Mask-Attention (MA)** (a soft-threshold variant of Mask2Former's mask attention, chosen because "the thresholding of mask prediction is changed from hard into soft, which suits action segmentation within a temporally continuous feature space"), then Self-Attention, then FFN. **So queries are grouped/tied to segments only through the predicted masks** — there is no explicit clustering step and no prototype library: the *trainable query embeddings themselves are the learned segment representations*, and which segment a query governs is decided by its predicted mask.
  - **Three output heads per layer** produce (i) per-query class `P^c ∈ R^{M×(K+1)}` (K+1 = classes + no-action), (ii) per-query mask `P^m ∈ R^{M×T}`, (iii) a **class-agnostic boundary** heatmap `P^b ∈ R^T` computed from a **single "global query"** obtained by aggregating *all* instance queries with an MLP (this is the "additional query to learn boundaries, capturing global information with minimal computational overhead").
  - **Inference = boundary-aware query voting (Algorithm 1)**: boundaries give class-agnostic segment proposals; inside each proposal, the masks of all queries are **summed** and the **majority-contributing query** wins; that query's class is assigned to the whole segment. Stated rationale: "for each segment proposal span, all the queries may be activated in the mask prediction but the query corresponding to the correct category always dominates." → the class of a segment is decided at **segment level**.
  - Training requires **ground-truth segment matching**, with three strategies (Fig. 5): **Ordered Class Matching** (queries aligned to class order — fixed), **Transcript Matching** (queries in action order, extras → no-action — reported to perform badly, "predisposes the queries towards positional grouping"), **Instance Matching** (Hungarian on a cost combining class probability and soft mask IoU; extras → no-action). Boundary GT is a Gaussian heatmap. Best = ordered-class matching; instance matching with 100 queries reaches 89.5% acc at 4.45G FLOPs.
  - **Efficiency claims (reported, Table 6 / paper text)**: BaFormer **1.63M params, 4.54G FLOPs, 0.139 s** inference on 50Salads; vs DiffAct **1.21M, 43.94G, 2.306 s** → "only 6% of inference time and 10% of FLOPs"; vs UVAST the "query-based voting mechanism significantly reduces inference time to 24%". **Training: 300 epochs, batch size 1, Adam (5e-4 for GTEA/50Salads, 1e-3 for Breakfast, decay 0.5), on a single NVIDIA RTX 3090.** Single-stage, no alignment/Viterbi post-processing.
- **Problem targeted**: TAS accuracy has been bought with dense frame-wise processing, complex multi-stage structures and expensive post-processing (Viterbi/alignment); BaFormer turns TAS into sparse **per-segment (instance) classification** with cheap boundary-driven group voting.
- **Datasets & metrics** (Table 6, all with the I3D/ASFormer pipeline above; 4-fold CV GTEA/Breakfast, 5-fold 50Salads):
  - GTEA → F1@{10,25,50} **92.0 / 91.3 / 83.5**, Edit **88.7**, Acc **83.0**
  - 50Salads → F1@{10,25,50} **89.3 / 88.4 / 83.9**, Edit **84.2**, Acc **89.5**
  - Breakfast → F1@{10,25,50} **79.2 / 74.9 / 63.2**, Edit **77.3**, Acc **76.6**
- **Params**: **1.63M** (Table 6; 1.55M / 4.02G in the CNN-backbone comparison of Table 7; 1.51M / 3.83G with single-level features in Table 10; 2.97G if decoder layers are cut to 3 — accuracy drops).
- **Small-data & low-dim-feature relevance**:
  - *Per-segment classification is exactly our business metric*: the voted class is assigned to the entire proposed segment, so a "dominant but wrong query" produces precisely our 51.6% whole-segment identity error — BaFormer does not protect against that, it institutionalises segment-level decisions. What it *does* give us is a cheap, query-count-controlled knob and a **fixed query-to-class assignment** ("ordered class matching") — with 9 classes + idle, M≈10 queries is a very natural configuration (they used 90/100 only because their class counts are 11/17/48).
  - *Low-dim features*: the only hard dependency on I3D is the frozen encoder producing `F_e ∈ R^{T×2048}`; the frame decoder is explicitly "any architecture designed for dense prediction tasks" — so a 144-d feature vector can be fed straight into the ASFormer-style decoder (or even a plain MS-TCN frame branch). No learned dependence on 2048 dims.
  - *Small-data*: single-stage + sparse queries means far fewer parameters to fit than a transformer encoder stack (1.63M), but the losses (Hungarian/mask matching + Gaussian boundary heatmaps + 300 epochs at batch size 1) need reliable segment GT — which we have (dense per-frame labels). Risk is mainly **over-segmentation/empty proposals on short videos** and the query-count/heavy-decoder hyperparameters tuned on datasets with ~20+ segments per video, whereas our videos average far fewer.
- **Verification notes**: fetched arXiv abs + arXiv HTML full text (architecture, query generation, three matching strategies, Algorithm 1 voting, implementation details), the official NeurIPS 2024 proceedings page (venue), GitHub API + raw LICENSE (absent) + README. NOT verified: no public statement about low-dim features; the 6%/10% efficiency ratios are the authors' own measurements (Table 6 FLOPs/time are stated to be measured "using the official codes in a consistent environment" on 50Salads).

### FACT: Frame-Action Cross-Attention Temporal Modeling for Efficient Action Segmentation
- **Venue/year**: **CVPR 2024**, pp. 18175–18185. Verified from the official CVF open-access page metadata + body: `citation_conference_title = Proceedings of the IEEE/CVF Conference on Computer Vision and Pattern Recognition`, `citation_publication_date 2024`, first/last page 18175/18185, and the printed citation "Proceedings of the IEEE/CVF Conference on Computer Vision and Pattern Recognition (CVPR), 2024, pp. 18175-18185".
- **URL**: https://openaccess.thecvf.com/content/CVPR2024/html/Lu_FACT_Frame-Action_Cross-Attention_Temporal_Modeling_for_Efficient_Action_Segmentation_CVPR_2024_paper.html (PDF: `.../papers/Lu_FACT_Frame-Action_Cross-Attention_Temporal_Modeling_for_Efficient_Action_Segmentation_CVPR_2024_paper.pdf`; supplemental: `.../supplemental/Lu_FACT_Frame-Action_Cross-Attention_CVPR_2024_supplemental.pdf`). **No arXiv version found** — see verification notes.
- **Code**: https://github.com/ZijiaLewisLu/CVPR2024-FACT — **MIT License** (GitHub API license=MIT; 113 stars). README warns: "We lost the original data and model weights in a disk failure. These models are replicated afterward, thus the performance slightly varies from those in the papers."
- **Core mechanism**: two **parallel branches** with **bidirectional cross-attention** between them, iterated over an input block + update blocks (Fig. 3):
  - **Frame branch** ("blue"): dense features processed by **dilated temporal convolutions** (the MS-TCN 9-layer dilated stack) to learn frame-level detail → `F1 = convolution(F0)`.
  - **Action branch** ("green"): `M` **action tokens** `A0 ∈ R^{M×D}` (initialized to 0, with **learned** positional encodings per token; frames use fixed sinusoidal encodings), updated by a transformer with self- and cross-attention over frame features → `A1 = transformer(A0, F1)`. So the *learned action tokens* play the role of segment/action prototypes ("we expect each action token to uniquely represent an action segment, thus encoding its action label and temporal location").
  - **Cross-attentions** (frame→action and action→frame) inside every update block let the branches refine each other iteratively ("iterative bidirectional information transfer"). Config: 1 input block, 3 update blocks (2 for GTEA), 6 self/cross-attention layers in the input block, 1 in each update block; temporal down/up-sampling (GRU+FC) in late blocks.
  - **Matching loss (Eq. 14)**: a Hungarian assignment (or the paper's one-to-many variant) matches action tokens to GT segments using a cost that sums (a) the probability that token `m` belongs to the GT class of segment `n` and (b) a **soft temporal IoU** between the segment interval and the token's mask `Λ ∈ [0,1]` (weighted by `β=0.2`); excess tokens go to a null class. Token counts: **60** for Breakfast/GTEA/EgoProceL, **300** for EPIC-Kitchen (one-to-many matching required ≥1500 tokens otherwise). Optional **video transcripts** (the sequence of actions) can be supplied at test time, replacing Hungarian matching by trivially known token↔segment matchings.
- **Problem targeted**: prior TAS either improves frame features with transformers or refines frame predictions with learned action features — expensive, and they ignore that frame- and action-level information are complementary. FACT does both simultaneously and cheaply; the matching loss is there to stop action tokens from being redundant and to make each token a unique segment encoding.
- **Datasets & metrics** (Tables 1–2; metrics: segmental Edit, segmental F1@{10,25,50}, frame accuracy; features: **I3D** for Breakfast/GTEA/EgoProceL (per supplemental: "For Breakfast, GTEA and EgoProceL, we use I3D[2] to extract framewise features to be consistent with prior works"), dataset-released features for EPIC-Kitchen; the *dimension* is not stated anywhere in the paper or supplement I extracted):
  - Breakfast (1716 videos, 10 recipes, 48 actions, avg 6.9 segments/video) → F1@{10,25,50} **81.4 / 76.5 / 66.2**, Edit **79.7**, Acc **76.2**
  - GTEA (28 videos, 11 actions, avg 33 segments/video — "a small-scale dataset to test learning with limited data") → F1@{10,25,50} **93.5 / 92.1 / 84.1**, Edit **91.4**, Acc **86.1**
  - EgoProceL (1055 videos, 130 actions, avg 21 segments/video) → F1@{10,25,50} **73.0 / 69.8 / 60.8**, Edit **75.7**, Acc **77.6**, AccB **88.0**
  - EPIC-Kitchen (633 videos, 3796 actions, avg 195 segments/video) → F1@{10,25,50} **27.6 / 25.3 / 18.5**, Edit **22.3**, Acc **20.8**, AccB **34.7**
  - Baselines in the same table (their own re-measurement): DiffAct on Breakfast F1@50 64.6 / Edit 78.4, LTContext Breakfast 77.6/72.6/60.1 / Edit 77.0, MS-TCN++ Breakfast 64.1/58.6/45.9 / Edit 64.9.
- **Params / efficiency (Table 4, "evaluated with the same hidden dimension on a 5-min video")**: FACT **1.9M params, 5.5 GFLOP** inference; MSTCN++ 1.0M/4.5G, ASFormer 1.1M/7.6G, UVAST 1.1M/2.9G, **LTContext 0.7M/7.8G**, **DiffAct 1.7M/63.0G**. Reported speed: "30% and 91% less GFLOP than the best competitors, LTContext and DiffAct", and "3.5 times faster than DiffAct"/"30 times faster than UVAST". Training: one NVIDIA Quadro RTX 6000, Adam lr 1e-4, Breakfast finishes in 20 hours (supplemental). **Number of epochs is not stated** in the extracted text.
- **Small-data & low-dim-feature relevance**:
  - **Their own small-data handling is a direct precedent for us**: on GTEA "we use 1 input block with 2 update blocks ... as it is a small-scale dataset and using fewer blocks reduces overfitting" (supplemental Table 1: GTEA 1 input + 2 update blocks; other datasets 1 + 3).
  - *Low-dim features*: the frame branch is convolutional over whatever `F0 ∈ R^{T×D}` is given; the action tokens live in the same `D`. A 144-d input needs only an initial projection (their `D` is the features' dimension, and the model is trained with hidden dim equal across branches). There is no architectural assumption of 2048 dims — but note that at 144-d the frame branch's capacity is far larger than the input, which is a classic overfitting configuration on 2.6k frames.
  - *Segment identity*: the action-token branch is the closest thing here to a "label-sequence prior" — tokens are learned action representations matched one-to-one to segments, and cross-attention lets action identity inform frames and vice versa. With only ~10 classes, 10–60 tokens is a plausible analogue of their 60-token GTEA setting. The matching loss requires segment-level GT (we have it). The transcript variant is *not* applicable to us (we have no textual transcripts), but note their reported transcript results are the highest (e.g. Breakfast F1@10 89.9) — i.e. FACT's headline numbers partly rely on extra supervision we don't have.

### Item 6 — "SSTCN" and sparse / hierarchical / multi-scale TAS methods: what actually exists

**Bottom line: there is no TAS method named "SSTCN" that I can find in a primary source.** Evidence:

- arXiv **title** search `SSTCN` → **"no results."** (query run with the required size=25; HTTP 200 + non-empty body; the page contains the literal string "no results.").
- arXiv **title** search `sparse temporal action segmentation` → **"no results."**
- arXiv **title** search `sparse attention action segmentation` → **"no results."**
- Web search for `"SSTCN" action segmentation` returned **no TAS paper** (top hits were unrelated — e.g. a turtle-diary PDF).
- **Important trap**: the string "SSTCN" *does* appear in the wild — but as **BaFormer's own label for a single-stage (1-stage) MS-TCN baseline**. BaFormer's Table 7 ("Performance of methods with similar running time…") lists a row `SSTCN | CNN | 1.71 GFLOPs | 0.080 s | 0.30 M | F1 27.0/25.3/21.5 | Edit 20.5 | Acc 78.2`, and the text says "Within the CNN backbone, i.e., SSTCN [15], BaFormer achieves outstanding enhancements, surpassing MSTCN by 3.8% in accuracy…". Citation [15] there is **MS-TCN**, and that row's numbers are identical to the `MSTCN1` (1 stage) row of BaFormer's Table 11 (1.71 GFLOPs, 0.080 s, 0.30 M, 27.0/25.3/21.5, 20.5, 78.2). So BaFormer's "SSTCN" = a single-stage MS-TCN baseline, **not a published method**. Do not cite "SSTCN" as a paper.

**Sparse / hierarchical / multi-scale methods that DO exist (arXiv title search, primary IDs)**:

- Title search `temporal action segmentation` → 25 hits; among the directly relevant, non-skeleton, supervised ones: `2405.15995` (BaFormer), `2411.01122` OnlineTAS (online baseline), `2503.18358` Cost-Sensitive Learning for Long-Tailed TAS, `2408.09919` Long-Tail TAS with Group-wise Temporal Logit Adjustment, `2309.15683` End-to-End Streaming Video TAS with Reinforce Learning, `2404.01518`/`2309.06276` unsupervised OT-based methods, `2312.12347` SMC-NCA semi-supervised. **No "SSTCN"**.
- For reference, the *sparse-query* direction in TAS that does exist is not called SSTCN: BaFormer (queries + boundary voting, NeurIPS 2024), FACT (action tokens, CVPR 2024), UVAST (query-based transcript, ECCV 2022, cited inside both), and the sparse **attention** method is **LTContext** (windowed + sparse long-term attention, ICCV 2023).

### "FactFormer" — honest answer

**No TAS method named "FactFormer" exists in any primary source I could reach.** What the name actually refers to:

- **FactFormer = "Factorized Transformer", a PDE surrogate model**: arXiv **2305.17560**, "Scalable Transformer for PDE Surrogate Modeling" (Zijie Li, Dule Shu, Amir Barati Farimani). I fetched the abs page: the abstract says "we propose Factorized Transformer (**FactFormer**), which is based on an axial factorized kernel integral… a learnable projection operator that decomposes the input function into multiple sub-functions with one-dimensional domain … instance-based kernel with an axial factorized scheme." **Completely different field (PDE surrogate modeling), no temporal action segmentation.**
- Checks for a TAS FactFormer: arXiv **title** search `FactFormer` → **"no results."**; web searches `"FactFormer" action segmentation` and `"FactFormer" transformer model 2025` returned **only** the PDE paper (and works that *use* it, e.g. a multimodal PDE surrogate citing "The backbone of our multimodal surrogate model is the FactFormer"), never a TAS paper.
- Conclusion: if a TAS "FactFormer" is being cited anywhere in our notes or in a related-work draft, it is almost certainly a **confusion with the PDE Factorized Transformer** and/or with **FACT** (Frame-Action Cross-Attention Temporal modeling, CVPR 2024) and/or **ASFormer** (BMVC 2021). None of those is named FactFormer.
