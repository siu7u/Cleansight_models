# Segment-level / whole-segment-identity methods in TAS — primary-source notes

Scope: six papers selected because they touch **segment-level structure / segment identity**, not merely boundary refinement.
Project context these notes are written against: 144-dim hand-crafted per-frame features (YOLO over 2×3 ROI grid), ~tens of thousands of frames, 8 test videos, ~9 classes + idle, segment-level business metric (edit / F1@k / insertion recall), best model MS-TCN++ (edit 51.08, F1@0.1 40.01, frame acc 53.98). Core failure: 51.6% of GT segments get a wholly wrong label.

Method: every fact below comes from a page I actually fetched (arXiv abstract page, arXiv HTML full text, or the paper's own tables parsed out of the HTML). Venues were cross-checked against Crossref. Anything I could not establish is marked `UNVERIFIED`.

### DIR-AS: Decoupling Individual Identification and Temporal Reasoning for Action Segmentation

- **Venue/year**: arXiv preprint v1, 04 Apr 2023 — `arXiv:2304.02110v1 [cs.CV]`. The arXiv abs page has **no `Comments:` venue field** and **no journal ref** (only the auto-generated DataCite DOI 10.48550/arXiv.2304.02110). Crossref `query.bibliographic` on the exact title returned no matching proceedings/journal record (top hits were unrelated papers). **UNVERIFIED — no peer-reviewed venue found**; treat as an unpublished preprint.
- **URL**: https://arxiv.org/abs/2304.02110
- **Code**: **none found.** The paper says only *"The code will be made available later."* (abstract, and §1). No repository URL appears anywhere in the full text. GitHub name search `DIR-AS action segmentation in:name` → `total_count: 0`. No license applicable.
- **Core mechanism**: A shared conv stem (conv kernel 7 / stride 4 temporal downsampling, then three dilated convs with rates 1/2/4) feeds **two decoupled branches**. (i) *Individual identification*: a local branch using sliding-window attention with **Temporal Pyramid Dilation (TPD)** (window 7 for GTEA / 51 for Breakfast, dilation rates 1, 2, 4 across 9 heads, embedding 512) and a global branch using **MHSA with Temporal Pyramid Pooling (TPP)** on key/value tokens (three average-pooling scales ≈1/2/3 s); 3 local-global layers; supervised frame-wise (CE). (ii) *Temporal reasoning*: cross-attention whose **queries are the coarse transcripts predicted by the identification branch** (plus an `End` token, padded to max length 41 GTEA / 100 Breakfast), followed by 8 self-attention layers, supervised as an **action-set / transcript** prediction (CE over the ordered action list). The two granularities are fused by a **parameter-free Viterbi action alignment** that enumerates durations for the transcript and maps it back to frames. Training is **decoupled**: joint end-to-end first (select best accuracy), then freeze branch (i) and fine-tune branch (ii) (select best edit). Regularisation: **Temporal Label Smoothness (TLS)** rolls targets by 1..τ to relax exact boundary alignment, **Categorical Label Smoothness (CLS)**, and Gaussian noise on input features (weights differ before/after decoupling).
- **Problem targeted**: **whole-segment identity + sequence structure, jointly with boundaries.** The paper's framing is explicitly "two inherent goals … *individual identification* … (discreteness) and *temporal reasoning* … (continuity)" and it notes previous work "takes advantage of frame-wise supervision, which cannot effectively tackle the evaluation metrics with different granularities". It does **not** claim that identification errors dominate; its stated motivating failure is **over-segmentation / boundary ambiguity**. Its own failure analysis (§C.2, Fig. 10) reports errors in the *other* direction: transcript prediction can **overlook short segments → under-segmentation**, and alignment can still leave a single segment "split into multiple sub-segments, which means a new over-segmentation issue". So: identity is decoupled, but *dominance of identity errors is not reported*.
- **Datasets & metrics** (Table 1, "Comparison with recent state-of-the-art methods"; feature = **I3D**, §4.2: "We use pre-trained I3D to project each video to visual features"):
  - GTEA → F1@{10,25,50} **94.3 / 93.4 / 84.5**, **Edit 89.7**, **Acc 82.8**
  - Breakfast → F1@{10,25,50} **76.2 / 71.0 / 58.2**, **Edit 76.6**, **Acc 74.7**
  - Abstract claims "+2.6%" acc on GTEA and "+1.2%" on Breakfast over prior SOTA.
  - Ablation (Table 2 "Results of appending different modules in series", GTEA split 1; cols = F1@10/25/50, Edit, Acc): stem only `50.00 / 44.49 / 34.86, 41.51, 71.20` → +local `45.95 … 39.26, 73.47` → +global `80.00 / 78.03 / 69.32, 71.45, 77.43` → +label smooth `85.00 / 82.85 / 70.71, 79.84, 79.39` → +temporal reasoning `91.67 / 91.67 / 83.33, 94.77, 84.27`. Paper's own reading: adding the conv stem increases F1 by ~40% and Edit by ~30%; the transcript module raises F1@50 by ~13%, Edit by ~15%, accuracy by ~5%. (Numbering quirk: the paper's §4.4 running text refers to this module ablation as "Table 3", contradicting its own caption "Table 2" — I follow the caption. §4.4 also calls the query/key table "Table 4", which matches its caption.)
  - Table 4 (GTEA, query/key choice): learned query tokens are worst (deep keys: Acc 79.76; shallow keys: 78.20); predicted transcripts as queries with shallow keys give `91.67 / 91.67 / 83.33, 94.77, 84.27` (text: "+4.7%" accuracy from using predicted transcripts as queries at both deep and shallow keys).
  - Table 3 running time (GTEA): ASFormer 0.1961 s/video, UVAST+alignment 0.1400, DIR-AS (no Viterbi) **0.0439**.
- **Params**: **not stated** (no parameter count anywhere in the full text; grep for `param`/`# param`/`parameters` found only a formula symbol and unrelated discussion).
- **Small-data & low-dim-feature relevance**: **Input-agnostic** — the network consumes only a `T × D` feature sequence (the conv stem is 1-D over time), so a 144-dim input is mechanically fine; nothing in the architecture assumes 2048 dims. Overfitting pressure is explicitly acknowledged and mitigated: locality is justified as "crucial for action segmentation suffering from **data insufficiency**", learned query tokens fail "especially on the small dataset that is unable to provide the inductive bias", and Gaussian-noise augmentation is used "to alleviate over-fitting". Caveat for this project: the whole win on GTEA comes from the **transcript head + Viterbi fusion**; if the transcript head itself puts the wrong label on a whole segment, Viterbi will faithfully bake that wrong label into a full segment.

### Temporal Segment Transformer for Action Segmentation

- **Venue/year**: arXiv preprint v1, 25 Feb 2023 — `arXiv:2302.13074v1 [cs.CV]`. Abs page has **no `Comments:` field, no journal ref**. Crossref bibliographic query on the exact title returned no matching record (top hits unrelated: SSRN / WACV-2026 / IVC papers on other titles). OpenAlex search likewise returned no matching work. **UNVERIFIED — no peer-reviewed venue found**; treat as an unpublished preprint.
- **URL**: https://arxiv.org/abs/2302.13074
- **Code**: **no official repository.** The paper contains no code link (grep for `github`/`code` finds only the arXiv page furniture). A **third-party, unofficial** repo exists: https://github.com/baiyang4/TST-action-segmentation — GitHub API reports `license: None`, 0 stars, description "TST: Temporal Segment Transformer for Action Segmentation". **UNVERIFIED** as the authors' code.
- **Core mechanism**: A **predict-and-refine** head on top of a **frozen** backbone (ASFormer, or MS-TCN) that emits frame probabilities + frame features. (1) **Segmentation → segments**: take argmax per frame and group consecutive identical labels into action segments. (2) **Segment encoder**: each segment representation = mean of its frame embeddings + an MLP of its one-hot category embedding (sum of the two terms). (3) **Frame encoder**: an MS-TCN branch (4 layers, local window doubled from size 2, taking the backbone's frame features from the 8th/9th layers) that improves frame representations cheaply, backpropagated while the backbone stays frozen. (4) **Segment decoder**, 2 layers, alternating two blocks: **segment-frame (SF) attention** — each segment attends only to frames inside its own or immediately adjacent segments via an additive attention mask, which *denoises* the segment representation — and **inter-segment (IS) attention** — a Transformer over segment representations with positional encodings, capturing temporal (anti-)correlations between segments (e.g. "washing" preceding "chopping"). (5) **Prediction heads**: segment classification (2-layer MLP + softmax, plus a `junk` class for unclassifiable segments) and **segment boundary regression** (2-layer MLP → offset of segment centre normalised by length + log-scale length change). (6) **Mask voting**: refined boundaries become binary segment masks; frame-level probability = weighted summation of masks × class probabilities (junk class dropped). Supervision uses **Hungarian matching on tIoU** between initial predicted segment masks and GT segments, dropping pairs whose matched tIoU is 0; losses are CE (classification) + smooth-L1 (boundary regression).
- **Problem targeted**: **whole-segment identity, explicitly.** The introduction states that hierarchical frame-level modelling "can lead to a number of errors, including incorrect ordering of the predicted action sequence, **incorrect action segment labels**, over or under-segmentation and errors in segment boundaries", and the fix is a dedicated segment-classification head operating on denoised segment representations. Boundaries are handled, but as a parallel task ("we adopt a simpler approach of performing the tasks concurrently").
- **Datasets & metrics**:
  - 50Salads (Table 1): MS-TCN + Ours → `83.9 / 82.7 / 72.9`, Edit **78.5**, Acc 82.6; ASFormer + Ours → `87.1 / 85.9 / 78.3`, Edit **82.4**, Acc **86.1**; ASFormer + ASRF + Ours → `87.9 / 86.6 / 80.5`, Edit **82.7**, Acc **86.6** (ASFormer alone: `85.1 / 83.4 / 76.0`, Edit 79.6, Acc 85.6).
  - GTEA (Table 2): ASFormer + Ours → `91.4 / 90.2 / 82.1`, Edit **86.6**, Acc 80.3 (ASFormer alone `90.1 / 88.8 / 79.2`, Edit 84.6, Acc 79.7).
  - Breakfast (Table 3): ASFormer + Ours → `77.5 / 72.3 / 59.5`, Edit **76.7**, Acc 73.7 (ASFormer alone `76.0 / 70.6 / 57.4`, Edit 75.0, Acc 73.5).
  - Component ablation (Table 4, 50Salads): backbone `85.1/83.4/76.0, Edit 79.6, Acc 85.6` → +segment decoder `86.5/85.1/77.6, Edit 81.3, Acc 85.8` → +frame encoder `87.1/85.9/78.3, Edit 82.4, Acc 86.1`.
  - Segment-encoder ablation (Table 5 "Ablation on segment encoder strategies on 50Salads"): frame emb ⊕ category emb `87.1/85.9/78.3`; frame only `86.2/84.9/78.1`; **category only** `85.6/83.9/76.8, Edit 79.6` — i.e. the *initial label* embedding carries real signal, and dropping it costs more than dropping the frame embedding.
  - SF-attention ablation (Table 6 "Ablation on segment-frame attention strategies in segment decoder", 50Salads): no SF `85.9/84.3/77.2, Edit 80.9`; **global** SF (attend to all frames) `86.6/84.8/77.7, Edit 81.5`; **local** SF `87.1/85.9/78.3, Edit 82.4`. Confirms the paper's claim that distant-frame attention is "challenging and in fact sometimes harmful".
  - Decoder layers (Table 7): 1 layer `85.3/83.8/76.7, Edit 80.0`; **2 layers best** `87.1/85.9/78.3, Edit 82.4`; 3 layers `86.9/85.3/78.2, Edit 81.2`.
  - Feature backbone: **not stated in this paper.** `grep -i i3d` returns **0 hits** in the full text; TST only ever refers to "the backbone's frame features" (ASFormer/MS-TCN). Marked **UNVERIFIED** for TST's own feature statement (the backbones it uses are I3D-based in their own papers).
- **Params**: **not stated** (no parameter count in the full text).
- **Small-data & low-dim-feature relevance**: Consumes only `T × D` frame features from a frozen backbone → a 144-dim input is acceptable. The trainable part is small and operates on `N` segments plus a 4-layer MS-TCN frame encoder, trained for only **60 epochs** with the backbone frozen — **low overfitting risk**, which suits tens of thousands of frames. Two caveats specific to this project: (1) with 51.6% of GT segments wholly mislabelled, the Hungarian matching that **drops tIoU-0 pairs** will supervise only a minority of segments, so the segment-classification head is trained on very few positives; (2) it can be stacked on **MS-TCN** as well as ASFormer (Table 1 shows MS-TCN + Ours works), which matters because MS-TCN++ is this project's best model. The paper's own finding that the **category embedding alone already yields Edit 79.6 / F1@10 85.6** shows a lot of TST's gain is just *renormalising the initial argmax label per segment* — a cheap, directly testable idea for whole-segment identity.

### BIT: Bi-Level Temporal Modeling for Efficient Supervised Action Segmentation

- **Venue/year**: arXiv **v2**, 07 Oct 2023 (`arXiv:2308.14900v2 [cs.CV]`); abs-page `Comments:` = "9 pages, 6 figures"; licence field = CC BY-NC-ND 4.0. **No journal ref.** OpenAlex returns the work as `type: preprint`, venue `arXiv (Cornell University)` — no published version indexed. Crossref bibliographic query found no matching record. **UNVERIFIED — no peer-reviewed venue found.**
- **URL**: https://arxiv.org/abs/2308.14900
- **Code**: **none found.** §4.1 footnote 3: *"We will release our code and model weights."* No URL given. GitHub name search `BIT action segmentation in:name` → `total_count: 0`; the authors' successor repo path `ZijiaLu/FACT` 404s; `https://zijia-lu.github.io/` returns HTTP 404. No license applicable.
- **Core mechanism**: A **bi-level** architecture that learns explicit **action tokens** standing for action segments, running frame-level and action-level modelling in parallel. (i) **Frame branch** = convolutions (dual dilated layers from MS-TCN++) producing refined frame features and an initial frame-probability estimate, supervised by a frame CE loss `L_f`. (ii) **Action branch** = a Transformer over a **fixed small set of `M` learned action tokens** with learned positional encoding, using cross-attention (tokens ← frames) then self-attention, producing token class probabilities `L_a`; each token's cross-attention row is the **alignment** from token to frames, i.e. the token's segment location. (iii) **Update blocks** (1 input block + **3 update blocks**) alternate single-head **token←frame** and **frame←token** cross-attention so each level sees the other's information; a **`L_c`** loss forces a token to attend to the frames of its matched segment and vice versa. (iv) **Set prediction**: the optimal token↔segment matching is found by **Hungarian matching** (one-to-one) or a **proposed 3-step one-to-many algorithm** (multiple segments must share the action class), with matching cost = token class probability + soft IoU between the segment and the frames the token attends to; unmatched tokens go to a `null` class. A **temporal smoothing loss `L_ts`** is applied to frame probabilities *and* to both frame↔token attention maps, which is the mechanism aimed at the over-segmentation/oscillation problem. (v) **Downsampling trick**: to keep cross-attention learnable when frames ≫ tokens, frames are pooled **one feature per predicted segment** (average pooling — deliberately not a fixed ratio, "as it removes features of short segments"), refined by a GRU, then upsampled by copying and merged with the original frames by an FC layer; the attention maps are down/up-sampled the same way. Final prediction = **average** of the frame-branch and action-branch outputs. **Transcripts**: when available, action tokens are initialised from action-class embeddings in the transcript, the matching becomes known, and inference speed is unchanged (unlike prior work that needs post-processing).
- **Problem targeted**: **whole-segment identity and sequence structure** — action tokens *are* segments; the action branch predicts each segment's class, and the one-to-many matching exists specifically so a token can cover multiple same-class segments in long videos. Efficiency is the other explicit goal. Boundaries are not a separate head (no boundary regression).
- **Datasets & metrics** (feature = "pre-extracted framewise features", dimension not stated numerically in text; §3.1 notes BIT can also be end-to-end):
  - **Table 1 "Action Segmentation Performance" (no transcript)** — Breakfast F1@{10,25,50} `80.6 / 75.9 / 64.7`, Edit **79.0**, Acc **75.5**; GTEA `94.8 / 92.8 / 82.6`, Edit **92.6**, Acc **82.0**; EgoProceL `76.9 / 74.1 / 64.0`, Edit **79.2**, Acc **88.0**; EPIC-Kitchen `35.9 / 30.6 / 20.1`, Edit **37.2**, Acc **31.3**. (Comparators in the same table: MS-TCN++ Breakfast `64.1/58.6/45.9, 64.9, 67.6`; ASFormer Breakfast `76.0/70.6/57.4, 75.0, 73.5`.)
  - **Table 2 "Action Segmentation Performance using Video Transcripts"** — Breakfast `89.9 / 85.6 / 73.7`, Edit **93.5**, Acc **84.5**; GTEA `96.1 / 95.6 / 87.5`, Edit **96.3**, Acc 84.0; EgoProceL `74.3 / 71.2 / 61.9`, Edit 87.2, Acc 80.5; EPIC-Kitchen `66.9 / 60.8 / 44.8`, Edit 75.2, Acc 58.2.
  - **Loss ablation (Table 3 "Effect of Different Losses")** — all four losses `79.1 / 75.5 / 65.5`, Edit 78.3, Acc 74.1; frame loss + smoothing only `50.1 / 45.7 / 36.8`, Edit 56.6, Acc 67.3; action losses + frame loss without smoothing `73.2 / 69.3 / 60.7`, Edit 72.7, Acc 72.2. → the **action-branch losses are essential** (removing `L_a`/`L_c` collapses F1@10 from 79.1 to 50.1).
  - **Efficiency**: "on Breakfast the inference time of BIT is **30 times faster than UVAST** and **6 times faster than ASFormer**" (Fig. 1(d) + text). Architecture size stated as 1 input + 3 update blocks; token counts 60 (Breakfast, GTEA), 200 (EgoProceL), 300 (EPIC-Kitchen). **No parameter count and no epoch count are stated.**
- **Params**: **not stated** (grep for parameters/million/FLOPs finds nothing).
- **Small-data & low-dim-feature relevance**: Only `T × D` features are needed → 144-dim is mechanically fine. The paper itself frames **GTEA (28 videos) as "a small-scale dataset to test learning with limited data"** and BIT is the top method there in its tables — evidence it tolerates small data. Token count must exceed the number of segments (their note: one-to-one matching on EPIC-Kitchen "requires at least 1500 tokens"), which is not a problem for ~8-video / ~9-class data. Being 30× faster than UVAST makes it cheap to test. Caveat: it needs a reasonable frame-branch initial prediction and per-video segment pooling; with many wrong whole-segment labels, the Hungarian matching still has a chance to align tokens to *predicted* segments (matching is against GT segments, tIoU-based, so badly mislabelled but well-localised segments are still matched and can be relabelled).

### Do We Really Need Temporal Convolutions in Action Segmentation?

- **Venue/year**: **IEEE International Conference on Multimedia and Expo (ICME) 2023**, pages **1014–1019**, DOI **10.1109/icme55011.2023.00178** — verified via Crossref (container-title "2023 IEEE International Conference on Multimedia and Expo (ICME)", `type: proceedings-article`, year 2023). Independently corroborated by researchr (`researchr.org/publication/DuSLQSS23`, which lists authors Dazhao Du, Bing Su, Yu Li, Zhongang Qi, Lingyu Si, Ying Shan and the ICME 2023 pages). arXiv abs page has no `Comments:` field; the HTML is `arXiv:2205.13425v2 [cs.CV] 22 Nov 2022`.
- **URL**: https://arxiv.org/abs/2205.13425
- **Code**: **none found.** No code link anywhere in the full text (grep for `github`/`code is available` yields nothing). No license applicable.
- **Core mechanism**: **Correction to the task brief:** this paper is **not MLP-based**. `grep -ci mlp` → **0** and `grep -ci mixer` → **0** in the full text; there is no MLP-based mechanism to extract. What it actually proposes:
  1. **Temporal U-Transformer (TUT)** — a *pure Transformer without any temporal convolution*, following the multi-stage MS-TCN recipe (one prediction-generation stage + `s` refinement stages). Each stage = FC input projection → encoder of `N` layers → decoder of `N` layers → FC classifier. Each **encoder layer begins with nearest-neighbour temporal downsampling (halving)**, then **local attention** (sliding window of size `w`, linear complexity) with **scale-shared learnable relative positional encoding** (layers at the same scale across stages share the RPE), then FFN; **instance normalisation** instead of layer norm. Each **decoder layer** upsamples (nearest neighbour) and uses **local cross-attention** whose keys/values come from the encoder layer of the same temporal resolution (no U-Net skipping/concatenation, to save memory). The temporal sampling is what gives the U-architecture its inductive bias — "adjacent frames are more likely to belong to the same class".
  2. **Boundary-aware loss** — the paper observes that the similarity distribution between a boundary frame and its neighbours depends on whether the frame is a **start** or an **end** frame, defines two **sign-function prior distributions** accordingly, extracts the anchor's **local-attention distribution** from the attention matrix, and minimises the **symmetric KL divergence** between them. It needs no extra module or annotation (boundaries are derived from class labels) and is applied only in the **first encoder layer and last decoder layer** (because temporal downsampling blurs high-level boundaries). Total loss = CE + MS-TCN truncated-MSE smoothing + β·boundary-aware.
- **Problem targeted**: **boundary discrimination**, plus efficiency on long videos. The abstract is explicit that the coarse resolutions introduced by the U-architecture "result in the misclassification of boundaries" and that the boundary-aware loss "enhance[s] the ability to recognize boundaries". It is **not** a whole-segment-identity method — the only identity-adjacent contribution is the same-class-neighbour inductive bias.
- **Datasets & metrics** (feature = **I3D**; §"Experimental Details": "We employ the I3D frame-wise features provided in MS-TCN++"):
  - Table 1 "Comparison with the state-of-the-art results on three datasets": 50Salads **TUT** `F1@10,25,50 = 89.3 / 88.3 / 81.7`, **Edit 84.0**, **Acc 87.2**; `TUT†` `87.7 / 87.1 / 79.9`, Edit 82.6, Acc 85.9 (the `†` variant matches the β=0 row of Table 7, i.e. **without the boundary-aware loss**). GTEA TUT `89.0 / 86.4 / 73.3`, Edit 84.1, Acc 76.1. Breakfast TUT `76.2 / 71.9 / 60.0`, Edit 73.7, Acc **76.0** (best accuracy in that table). Comparators include MS-TCN++ and ASFormer as printed in the same table.
  - **Attention vs 1D convolutions** (appendix, Table 4; 50Salads, no RPE): Attention `87.7 / 87.1 / 79.9`, Edit 82.6, Acc 85.9 vs Convolution `82.8 / 81.3 / 74.1`, Edit 75.5, Acc 85.2 — the paper's headline "we do not need temporal convolutions" evidence (replacing every local-attention module with a 1D conv of the same kernel size costs ~7.3 Edit).
  - Architecture × attention pattern (Table 3): standard architecture + full attention `4.6 / 2.8 / 1.4`, Edit 3.3, Acc 62.8, 18.7 GB; U-Transformer + full attention `35.1 / 25.4 / 9.8`, Edit 31.9, Acc 43.8, 9.9 GB; U-Transformer + local attention `86.5 / 85.3 / 76.9`, Edit 80.6, Acc 84.4, **2.8 GB**. Text: *"Full attention fails regardless of the architecture, showing that **training on small data requires sparser attention patterns**."*
  - Window size (Table 5): w=11 `78.9/77.0/70.1`; w=31 `84.3/83.0/75.6`; **w=51 best** `86.4/85.4/78.6, Edit 80.5`; w=71 `85.7/84.2/78.2`; w=91 `85.2/83.5/76.7`.
  - Boundary-loss weight β (Table 7 "Effect of β which is the weight of the proposed boundary-aware loss"): β=0 `87.7/87.1/79.9, Edit 82.6, Acc 85.9`; β=0.01 `88.2/87.5/80.6, Edit 83.1, Acc 86.2`; β=0.02 `89.3/88.3/81.7, Edit 84.0, Acc 87.2`.
- **Params**: **not stated** (no parameter/FLOP/MAC count anywhere; the only parameter-related remark is that RPE adds parameters whose count depends on window size and heads, which is why RPE is disabled in the architecture ablations).
- **Small-data & low-dim-feature relevance**: Accepts any `T × D` input, so 144-dim is fine. It has the single most quotable small-data claim of the six: *"Full attention fails regardless of the architecture, showing that training on small data requires sparser attention patterns"* — and the full-attention rows collapse to ~4.6 F1@10 / 62.8 acc, which is a strong warning against vanilla global self-attention on this project's data size. However, TUT's design is aimed at *very long* videos (minutes-long, thousands of frames) and profits from the U-shaped downsampling; on ~tens of thousands of frames with only ~9 classes, the U-shape plus multi-stage refinement may be more capacity than needed. Its relevance to this project is mostly (a) the empirical warning about full attention, and (b) the model-agnostic boundary-aware loss regulariser (no extra parameters, derived from labels only), which could be bolted onto MS-TCN++ — but note it targets **boundaries**, not the 51.6% whole-segment label confusion.

### Activity Grammars for Temporal Action Segmentation

- **Venue/year**: **NeurIPS 2023** — arXiv abs-page `Comments:` field states "**Accepted to NeurIPS 2023**"; Crossref independently confirms container-title **"Advances in Neural Information Processing Systems 36"**, year 2023, pages **75413–75433**, DOI **10.52202/075280-3296**. (The NeurIPS 2023 proceedings PDF also appears in search results at proceedings.neurips.cc.)
- **URL**: https://arxiv.org/abs/2312.04266
- **Code**: **https://github.com/gongda0e/KARI** — GitHub API: description "Activity Grammars for Temporal Action Segmentation (NeurIPS 2023)", 14 stars, `license.spdx_id = **MIT**`; the repository's `LICENSE` file begins "MIT License / Copyright (c) 2024 Dayoung Gong". The paper itself points to this repo as "the official GitHub repository".
- **Core mechanism**: A **model-agnostic post-hoc sequence decoder** in three steps. (1) **KARI grammar induction**: from the training action sequences of one activity, induce a **probabilistic context-free grammar (PCFG)** with two rule types — **AND** rules (`V → α`, imposing a temporal order over a sequence of terminals/variables) and **OR** rules (`V → V₁[p₁] | … | Vₙ[pₙ]`, alternatives). Induction uses two concepts: **key actions** (the `N_key` most frequent actions, present in every training sequence, used to split each sequence into three sub-sequences *before / between / after* the key actions) and **temporal dependency** (temporally dependent actions → AND rules; independent actions, and independent groups, → OR rules). **Recursive rules** are introduced specifically so the grammar generalises to **unseen** action sequences. (2) **BEP parser**: a **Breadth-first Earley Parser** transforms the frame-level probability matrix `Y_{1:T}` from any TAS network into a **grammar-consistent action sequence** `a*` (a priority queue over states; BEP prioritises **low-depth** states to escape cycles and OR nodes, whereas the compared GEP prioritises highest-probability states and gets trapped in local optima). (3) **Segmentation optimisation**: Viterbi-like dynamic programming assigns optimal **action lengths** to `a*` by maximising the product of frame probabilities.
- **Problem targeted**: **sequence-of-segments structure — this is the most on-target paper of the six for whole-segment label confusion.** It constrains *which ordered sequences of segment labels are admissible*: parsing forces the output transcript to be derivable from the induced grammar, so label sequences the grammar cannot generate are **rejected outright** regardless of how confident the frame classifier was. The paper's qualitative results (Fig. 5) state that the induced grammar "efficiently **insert missing actions** and **removes out-of-context actions**" in ASFormer's output. It does **not** re-estimate per-frame features or boundaries; it rewrites the *label sequence*.
- **Datasets & metrics** (feature = **I3D**, "We used I3D features provided by [MS-TCN]"; input sampling rate adjusted to 50 for Breakfast / 100 for 50 Salads; base models ASFormer and MS-TCN):
  - **Table 3 — 50 Salads** (cols: edit, F1@10, F1@25, F1@50, acc). ASFormer as printed in the original paper `75.0 / 76.0 / 70.6 / 57.4 / 73.5`; **ASFormer reproduced `76.5 / 83.8 / 81.7 / 74.8 / 86.1`**; **ASFormer + KARI `79.9 / 85.4 / 83.8 / 77.4 / 85.3`**; ADIOS-AND `58.3 / 70.0 / 68.0 / 59.4 / 76.2`; ADIOS-OR `61.1 / 72.0 / 70.1 / 62.4 / 78.9`. MS-TCN reproduced `62.4 / 69.5 / 65.3 / 55.7 / 75.2`; **MS-TCN + KARI `66.7 / 75.1 / 73.2 / 60.8 / 76.7`**.
  - **Table 4 — Breakfast**. ASFormer reproduced `75.6 / 77.3 / 72.0 / 59.4 / 74.3`; **ASFormer + KARI `77.8 / 78.8 / 73.7 / 60.8 / 74.0`**; MS-TCN reproduced `69.7 / 70.7 / 65.1 / 52.6 / 69.4`; **MS-TCN + KARI `74.9 / 74.6 / 68.7 / 55.1 / 68.8`**.
  - **Net effect (my subtraction from the tables' own rows, vs each method's *reproduced* baseline)**: 50 Salads ASFormer **+3.4 Edit, +1.6/+2.1/+2.6 F1@10/25/50, −0.8 acc**; Breakfast ASFormer **+2.2 Edit, +1.5/+1.7/+1.4 F1, −0.3 acc**; 50 Salads MS-TCN **+4.3 Edit, +5.6/+7.9/+5.1 F1, +1.5 acc**; Breakfast MS-TCN **+5.2 Edit, +3.9/+3.6/+2.5 F1, −0.6 acc**. Gains are therefore **concentrated in the segment-level metrics (edit, F1@k) with frame accuracy flat or slightly down** — exactly the profile this project wants.
  - **Critical negative result**: a *bad* grammar actively destroys performance — ADIOS-induced grammars push 50 Salads ASFormer from a reproduced 76.5 edit down to **58.3** (ADIOS-AND) / 61.1 (ADIOS-OR). Grammar quality is everything.
  - **Grammar generalisation** (synthetic evaluation, Tables 1 and 2; precision/recall of induced grammars parsing **unseen** sequences): grammar I — ADIOS-AND `0.97 / 0.08`, ADIOS-OR `0.99 / 0.25`, **KARI `0.93 / 0.98`**; grammar II — ADIOS-AND `0.98 / 0.06`, ADIOS-OR `1.00 / 0.33`, **KARI `0.92 / 0.96`**. This is the paper's core argument: prior grammar inducers are precise but essentially cannot cover unseen sequences (recall 0.06–0.33), while KARI does.
  - **Ablation (Table 5, 50 Salads, ASFormer)**: full `79.9 / 85.4 / 83.8 / 77.4 / 85.3`; **without recursive rules** `69.2 / 77.1 / 74.9 / 67.4 / 80.9` (−10.7 edit); **without key actions** `62.6 / 72.9 / 70.5 / 63.0 / 78.8` (−17.3 edit). Both components are necessary.
  - Parser choice (Table 6 "BEP vs GEP"): BEP (queue 20) `79.9 / 85.4 / 83.8 / 77.4` beats GEP (queue 10) `73.3 / 81.1 / 79.1 / 72.9`. Key-action count (Table 7 "Ablation on N_key"): `N_key = 3` best (`79.9 / 85.4 / 83.8 / 77.4 / 85.3`), while `N_key = 1` gives `73.0 / 81.5 / 79.9 / 72.6 / 83.5` and `N_key = 6` gives `68.4 / 75.2 / 73.3 / 64.2 / 77.9` — the key-action hyper-parameter is sensitive.
- **Params**: **not stated** for the base models; more importantly, **the grammar module adds no trained network parameters** — it operates on the base model's output probabilities (grammar induction is a counting/statistics procedure over training transcripts; parsing is search). It does add **inference-time compute** (the paper limits the parser's queue size because "the parser, without limitation, fails to complete parsing within a reasonable time").
- **Small-data & low-dim-feature relevance**: **Strong and directly applicable.** It is completely **model-agnostic and feature-agnostic** — it consumes only a frame × class probability matrix, so a 144-dim-feature MS-TCN++ drops straight in with **zero retraining**, and it attacks precisely the failure mode named in the project ("whole-segment label confusion") by refusing label sequences that are not derivable from the activity grammar. Risks for *this* project: (1) the grammar is induced per activity from training transcripts, so it needs a **recurring, learnable sequence structure** — with only ~8 videos and 9 classes + idle spread over several activities, there may be too few sequences per activity to induce a stable grammar (in their Tables 1/2 they evaluate with 100 synthetic grammars of 20 variables/20 terminals for stability, suggesting the method expects many sequences); (2) `N_key` and the parser queue size need tuning per dataset and the ablation shows large sensitivity; (3) the paper explicitly acknowledges failure cases where "the grammar sometimes deletes certain actions", compounded by "inaccurate identification of actions by the segmentation model". Expect a gain in edit/F1@k with some risk to insertion recall.

### Temporal Action Segmentation: An Analysis of Modern Techniques

- **Venue/year**: **IEEE Transactions on Pattern Analysis and Machine Intelligence (TPAMI)**, **vol. 46, pp. 1011–1030, 2024** — verified via Crossref (container-title "IEEE Transactions on Pattern Analysis and Machine Intelligence", `type: journal-article`, DOI **10.1109/tpami.2023.3327284**). The arXiv abs-page `Comments:` field says "19 pages, 9 figures, 8 tables, **TPAMI 2023**" (manuscript received October 19, 2022; the HTML is `arXiv:2210.10352v5 [cs.CV] 21 Oct 2023`). Authors: Guodong Ding, Fadime Sener, Angela Yao (NUS / Meta Reality Labs).
- **URL**: https://arxiv.org/abs/2210.10352
- **Code**: The survey's own curated resource list — **https://github.com/nus-cvml/awesome-temporal-action-segmentation** (given in the abstract and §I). GitHub API: 253 stars, description "A curated list of awesome temporal action segmentation resources", `license: None` (no license file detected).
- **Core mechanism / coverage**: A taxonomy + analysis in two axes. **(A) Frame-wise representations** (§III-A): IDT/Fisher-Vector *hand-crafted* features vs deep backbones; I3D is described concretely — Inception-V1 with inflated 2D kernels, pre-trained on Kinetics, two streams (RGB + TV-L1 optical flow) each giving **1024D**, concatenated into a final **2048D** representation. **(B) Temporal vs sequential modeling** (§III-B): *temporal* modelling (RNN/GRU, TCN encoder-decoder vs multi-stage, Transformers) operates at frame level; *sequential* modelling operates at **segment level** (HMMs and Generalized Mallows Models, decomposed into a **context model** `p(c_{n+1}|c_n)`, a **length model** `p(ℓ_n|c_n)` (Poisson in practice), and a **visual model** `p(x_t|c_n)`), with Viterbi / FIFA inference. Also over-segmentation & boundary refinement, supervision levels, and evaluation measures.
- **Problem targeted**: Both — it is a survey — but its **most relevant content for this project is the segment-level/sequential half and the research-gap section**, which argue explicitly for segment-level rather than frame-level formulation.
- **Design choices that the survey says actually change results (quotes + numbers)**:
  - **Segment-level losses (research gap, §V)** — the single most relevant claim here: *"Exploring how to add sequence-based losses, such as edit scores that penalize segment-wise mistakes, into the learning process is an interesting but under-explored direction. Segment-level losses readily coincides with the first interpretation of the TAS task … We recommend a greater emphasis on solving the task at the segment level and anticipate that it can greatly reduce the current issues with oversegmentation."*
  - **Transformers / small data** (§III-B1): *"the transformers lack inductive biases and require large video corpora for effective training. Yet existing datasets for TAS are relatively small, making it difficult for large transformers to develop effective representations."* Also: self-attention "might not acquire meaningful weights from large spans of inputs".
  - **RNN/GRU** (§III-B1): *"The memory capacity of a frame-wise RNN or GRU, however, does not span long enough to capture the sequential relationship between actions"* — consistency with this project's finding that GRU is worse.
  - **TCN shape** (§III-B1): encoder-decoder TCNs' pooling "may harm the prediction accuracy at action boundaries", whereas MS-TCN "preserves the full temporal resolution, especially the boundary information, but comes at a cost of higher computation".
  - **Boundary / smoothing post-processing** (§III-B3): *"Smoothing with a Gaussian kernel promotes the continuity of actions in a narrow local temporal window and is **highly effective in raising segmentation metrics**"*; soft boundaries (linear or sigmoidal action-probability transitions, Fig. 9) are argued to beat hard one-hot transitions.
  - **Length model** (§III-B2): *"The explicit modeling of lengths is necessary to avoid producing unreasonably long action segments."*
  - **Hard ordering transitions** (§III-B2, CTE Eq. 12): it *"imposes a hard transition; new frames must remain the same action label as the previous frame or transition to the next action label observed in the ordering [K]"* — a directly reusable, cheap constraint on the admissible **sequence of segment labels** (a sequence of hard states, conceptually the strictest relative of the activity-grammar idea).
  - **Features** — the survey's own Table V ("Performance of supervised TAS methods on GTEA and Breakfast") provides the numbers. MS-TCN on **Breakfast**: IDT features `F1@10,25,50 = 58.2 / 52.9 / 40.8, Edit 61.4, MoF 65.1` vs **I3D** `52.6 / 48.1 / 37.9, Edit 61.7, MoF 66.3` — i.e. hand-crafted IDT gives *better* segment F1 than I3D on Breakfast while I3D gives slightly better accuracy, and the two are a wash on edit. MS-TCN on **GTEA**: I3D `85.8 / 83.4 / 69.8, Edit 79.0, MoF 76.3` vs **fine-tuned I3D (FT)** `87.5 / 85.4 / 74.6, Edit 81.4, MoF 79.2` — fine-tuning the features is worth ~+2.9 MoF / +2.4 Edit.
  - Other survey tables: **Table III** ("Temporal dynamics of three TAS datasets") gives the **repetition / order-variation scores** — 50Salads r=0.08, v=0.02; Breakfast r=0.11, v=0.15; Assembly101 r=0.18, v=0.05 (higher v = looser ordering constraints). **Table IV** ("Imbalance Ratio (IR) on four TAS datasets") gives **IR** — GTEA **24**, 50Salads **6**, Breakfast **639**, Assembly101 **2604**; the survey calls the long-tailed distribution of action duration "an overlooked aspect of per-frame classification formulation" (and their Fig. 4 reports the Breakfast head class 'fry pancake' is "MATH more frequent than the tail class 'take butter'" — the multiplier is a rendered formula I could not read as a number).
  - **Background/idle frames** (§II-B4): *"In most existing works, the background class is treated equally as other action classes and used during training and inference."* — relevant to this project's `idle` class.
  - The survey also notes no empirical study compares pre-computed features vs end-to-end training, and that pre-computed features "tend to favour static cues, e.g. scene components, within frames" (citing [161,162]).
  - **Notably absent**: the survey's taxonomy contains **no MLP-based family** for TAS (`grep -ci mixer` → 0) and no MLP mechanism discussion, so it offers no support for an MLP-Mixer-style reading of paper 4.
- **Params**: **not stated** — the survey does not tabulate parameter counts for any method.
- **Small-data & low-dim-feature relevance**: High, as a design-guide rather than a model. It legitimises non-I3D inputs (IDT is a hand-crafted baseline in its own tables, and its empirical comparison even favours IDT on Breakfast segment F1), warns that Transformers need corpora that TAS datasets do not have, warns that full attention is fragile, and explicitly names **segment-level losses / segment-level formulation** as the under-explored direction that should reduce over-segmentation. The **IR = 639 (Breakfast) / 2604 (Assembly101)** figures and the observation that "background is treated equally" are directly usable arguments for class-balanced or segment-level losses on this project's 9-class + idle, ~tens-of-thousands-of-frame dataset. The **hard-ordered-transition** and **Poisson length-model** components of the HMM formulation are cheap, parameter-light segment-level priors that could be layered on MS-TCN++ outputs without retraining — but they require a known ordering/transcript, which is precisely what is uncertain when 51.6% of segments get the wrong label.

## Cross-cutting synthesis for this project

**Mechanisms that plausibly attack whole-segment identity confusion** (ranked by how directly they act on the *segment label sequence*, which is the project's actual failure):

1. **Activity-grammar decoding (KARI)** — the only paper of the six that *constrains which ordered label sequences are admissible at all*. Model-agnostic, feature-agnostic, **0 extra trained parameters**, drops on top of MS-TCN++ output probabilities, and its measured gains land exactly on edit/F1@k (+2.2 to +5.2 edit; frame accuracy flat) rather than frame accuracy. MIT-licensed code. Main risk is grammar induction on very few training sequences per activity, and `N_key` sensitivity (Table 7).
2. **BIT action tokens + set prediction (Hungarian / one-to-many matching to GT segments)** — represents segments explicitly as tokens whose whole identity is predicted at action level, and is fast (30× UVAST). Its loss ablation shows action-branch losses are load-bearing (F1@10 collapses 79.1 → 50.1 without them).
3. **TST segment classification head + inter-segment attention + mask voting** — directly re-predicts each segment's label from a denoised segment representation and lets segments attend to each other (the "washing precedes chopping" kind of correlation is exactly whole-segment identity evidence). Its category-embedding ablation (Edit 79.6 with category embedding alone) shows **per-segment label re-normalisation alone** is already a strong, cheap baseline. Stacks on MS-TCN as well as ASFormer.
4. **DIR-AS decoupled transcript (action-set) branch + Viterbi alignment** — the closest thing to "predict the label sequence first, then assign durations", which by construction fixes whole-segment identity before boundaries. Caveat: its reported failures are under-segmentation of short segments and residual over-segmentation, not identity dominance; and its own ablation shows the win comes from the transcript head (F1@50 +13%, Edit +15%).
5. **Survey's HMM hard-ordered-transition + Poisson length model, and its call for segment-level (edit-style) losses** — cheap, parameter-light priors/objectives on segment sequences; the survey explicitly names this as under-explored.
6. **Not on target for identity**: TUT/ICME-2023 (boundary-aware loss + local attention; boundary refinement and long-video efficiency only) — though its "full attention fails on small data" ablation (F1@10 4.6, acc 62.8) and its parameter-free boundary-aware loss are useful evidence/regularisers.

**Ideas that appear more than once across these sources**: restricting attention to nearby frames is better than global attention (TST Table 6 local vs global SF attention; TUT full attention collapses and local attention wins; DIR-AS builds a *local* window branch for "data efficiency"); segment-level / sequence-level objectives rather than only frame-wise CE are called out as under-explored by the survey and are the explicit design of DIR-AS, TST, BIT and KARI; and explicit **segment-length modelling** appears in TST (boundary-regression length head), BIT (per-segment pooling), the survey's HMM length model and DIR-AS's Viterbi duration enumeration.

**Gaps / warnings recorded**: none of the six papers reports parameter counts (all "not stated"), so no param-matched comparison is possible from these sources; TST, DIR-AS and BIT were **not found in any peer-reviewed venue** (Crossref + OpenAlex negative) and none has an official, licensed code release (only KARI and the survey's resource list have public repos, and only KARI has a license — MIT).
