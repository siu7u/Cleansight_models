## 1. 为什么要校验"降阈值"这条方案

第 2 轮的结论指向一个具体动作：重跑自动标注、对稀有类放宽 `conf`。
依据来自两处：

- 构建 auto 数据的 `framework/experiments/auto-annotate-yolo11.yaml` 用的是**全局 `conf: 0.25`**；
- 仓库自己的 `docs/features/INPUT_DESIGN_PROPOSAL.md` §3 把「检测侧扩召回（逐类降阈值 / 换 g2 权重 /
  补帧）」列为**"最高天花板，但有资源前置"**。

但"降阈值有用"这件事**从未被实测过**。本轮用本地能拿到的全部材料把它测掉。

## 2. 尝试 A：`outputs/annotations/*.json` 能不能直接回答？→ **不能，且中途更正过一次错误结论**

`outputs/annotations/*.json` 是自动标注流水线的原始轨迹，**逐帧带 `conf`**，且与手动数据集有
**12 个视频重合**（人工框可当真值）。看起来是一条免推理的捷径。

**第一次读数**：在 `enabled` 条目里，逐类召回从 `conf≥0.05` 到 `conf≥0.25` **完全持平**
（`scope_distal_end` 10.3%、`syringe` 15.2%），据此我一度得出"降阈值没用"的结论。

**随即核查该结论的前提**（`enabled` 条目 conf 分布）：

| 类别 | enabled 条目 | **非零最小 conf** | 非零 p1 | 中位 |
|---|---:|---:|---:|---:|
| hand | 96,902 | **0.2500** | 0.2540 | 0.520 |
| scope_control_body | 34,140 | **0.2500** | 0.2523 | 0.454 |
| scope_mid_section | 32,599 | **0.2500** | 0.2530 | 0.484 |
| scope_distal_end | 4,093 | **0.2505** | 0.2637 | 0.767 |
| syringe | 7,442 | **0.2501** | 0.2517 | 0.620 |
| air_gun | 854 | **0.2501** | 0.2525 | 0.693 |

**每个类的非零最小 conf 恰好是 0.2500** —— 说明推理阶段就用了 `conf=0.25`，
**低于该值的检测从未产生**。所以"召回持平"是**截断假象**，不是"降阈值没用"的证据。
**该结论已作废**（这正是本项目"先测再断言"纪律要拦住的错误）。
另：`short_brush` / `brush_tip_out` 在 enabled 轨迹里**根本不出现**。

## 3. 尝试 B：实跑低阈值推理 —— 本轮的核心实验

**材料（全部本地）**：

| 角色 | 来源 |
|---|---|
| 图像 | `datasets/cleansight-ActionMixed/images/<split>/*.jpg`（**手动数据集的采样帧**，与人工框逐帧对齐） |
| 真值框 | `datasets/cleansight-ActionMixed/frames/<split>/*.txt`（**人工 videorectangle**） |
| 检测器 | `legacy/.../versioned_weights/yolo-small-v3`（syringe / air_gun / scope_distal_end）与 `yolo-large-v3`（hand / scope_control_body / scope_mid_section） |

**口径**：`conf=0.001` 推理 → 离线按阈值过滤 → **逐帧一对一贪心匹配**（按 conf 降序，IoU≥0.35）。
必须一对一：低阈值下噪声框极多，"任意重合即算命中"会把噪声计成真框（本脚本第一版就踩了这个坑）。

**样本**：200 帧/视频 × 16 视频 = 3,200 帧（结果与 60 帧/视频的冒烟一致）。

## 4. 结论：方案要改——**分级阈值只解决一半问题**

### 4.1 `scope_distal_end`：**降阈值近乎免费地翻倍召回** ✅

`0.25 → 0.10`：召回 **37.8% → 50.2%**（+12.4pp，相对 +33%），而精度只从 **99.7% 掉到 96.0%**。
这是本轮唯一一个"白捡"的改善：**该类的检测器很准，只是被阈值切掉了将近一半真框。**

### 4.2 `syringe`：**任何阈值都救不回来，必须换检测器** ❌

召回 `3.2% @0.25` → `11.1% @0.05`，而精度始终 **≈1%**。
即该检测器对 syringe 基本没有可用输出；**降阈值只会灌进噪声**。
`air_gun` 在抽样帧里没有人工框（support=0），无法评估；
`short_brush` / `brush_tip_out` **本机没有对应权重**，且它们在 auto 的标注 JSON 里**根本不出现**。

### 4.3 高频三类：**现行 0.25 已经是合理的精度取向工作点** ⚖️

降到 0.10 能换来 +8~15pp 召回，但精度掉 25~40pp（hand 65.3→32.7、scope_mid 71.3→44.2）。
对 ROI 聚合特征是否划算**没有免费答案**，属于可调旋钮而非修复。

### 4.4 对第 2 轮方案的正式更正

| 原方案 | 本轮实测后的更正 |
|---|---|
| "重跑自动标注、**对稀有类放宽 conf** 即可恢复覆盖" | **只对 `scope_distal_end` 成立**（近乎免费）；`syringe` 类必须**换更好的检测器**，降阈值无效；`short_brush`/`brush_tip_out` 在现有流水线里根本没被检出过 |
| 更上游的**因果前提**："判别力 100% 来自稀有类通道，所以把这些通道补回来就能涨 acc" | ❌ **撤回**（§0）：10 折配对检验显示砍掉稀有类通道对帧准确率**没有可测影响**（p=0.557）。因此"补回稀有类覆盖 → 帧准确率上升"这条推理**目前没有证据支持** |

**也就是说：§3 的检测器事实是硬的（syringe 检不出、scope_distal_end 被阈值切掉一半），
但"把它修好就能涨 acc"这一跳没有被验证。** 修复优先级仍可据此排（把检测器做好本身是对的），
但**不能承诺帧准确率收益**。

## 5. 修正后的整体状态（3 轮汇总）

| 命题 | 证据 | 状态 |
|---|---|---|
| 旗舰 `acc` 53.92 低于平凡基线 55.25 | 8 seed test 中位 | ✅ 成立 |
| 解码/校准轴打不动（逐类偏置**泄漏上界** 57.52） | 第 1 轮 | ✅ 成立 |
| 训练轴（6 条臂）、集成、平滑、类别否决都 ≤ +1.5pp | 第 1 轮 | ✅ 成立 |
| 更多数据（合并集）→ −6.17pp 负迁移 | 第 2 轮 | ✅ 成立 |
| auto 的稀有类框只有人工框的 5%~21% | 直接统计 | ✅ 成立 |
| 小目标检测器的稀有类召回极低，且**降阈值救不回来**（syringe 精度恒 ≈1%） | 第 3 轮实跑 | ✅ 成立 |
| "分水岭在框的来源（人工框 vs YOLO 框）" | 单折 +7.01 / −11.38 | ⚠️ **量级作废**；10 折下 auto −5.06 稳定、manual 与基线不可区分 |
| "判别力 100% 来自稀有类通道" | 单折消融 | ❌ **撤回**（p=0.557） |

**结论：3 轮下来，"帧准确率为什么上不去"仍然没有可信的根因。**
目前能确定的只有：**在现有 144 维 ROI 特征 + 现有数据规模下，无论用深度模型、树模型还是线性模型、
无论怎么调工作点，test 上的帧准确率都封顶在平凡基线附近（55±1），而用 test 标签拟合偏置的
泄漏上界也只有 57.5。** 上表里被证伪的两条都曾是"看起来最有希望"的解释。

**下一步需要用户决策的资源/口径**（不再是"重跑标注"这一条）：

1. **换输入源**（唯一没有被证伪的方向）：project-16/18 的**像素**（逐帧图像 embedding / 光流），
   或对目标批次重新人工标注检测框。现有 auto 与 manual 两套框都试过，ROI-144 上都不够。
2. **重定目标口径**：`acc` 在本数据上几乎完全由类别先验决定（第 1 轮已量化），
   建议改用先验稳健口径（段覆盖 / 平衡准确率）作为验收指标。
3. 若坚持 `acc`，则需接受"先做一个**目标批次的视频/像素**可用性决策"才能继续。


**已知限制**：
1. 检测器是 **legacy v3** 权重，而 auto 数据集用的是 `yolo11s-g1/g2`（本机没有）——本实验验的是
   **各类的可检出性与阈值敏感性**，不是具体权重的绝对读数；
2. 图像来自**手动数据集**，对 legacy v3 而言偏同源，故绝对召回偏乐观；但"syringe 无论怎么降阈值
   都是 ~1% 精度"与"scope_distal_end 在 0.10 处精度仍 96%"这两条在 60 帧/视频与 200 帧/视频
   两个样本上完全一致，作为**分类结论**是稳的；
3. `air_gun` 抽样帧真值 support=0，未评估；`short_brush` / `brush_tip_out` 本机无权重，未评估；
4. **凡涉及视频级留出的读数（§0 的两张表）都必须按逐折分布读**：留出集只有 3~4 个视频时单折
   读数完全不可用，本系列前两轮正是栽在这一点上；
5. `acc` 本身在 8 视频 test 上跨 seed 摆幅 4.32pp，任何 <2pp 的读数都不可判读。
