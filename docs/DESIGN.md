# CleanSight 模型仓库设计准则

> 面向：在本仓库新增模型、改动评估框架、或做重构的人。
> 本文是**仓库级**的抽象取舍准则，与具体框架实现解耦；框架的用法/接入见
> [`../framework/README.md`](../framework/README.md) 与 [`MODEL_ONBOARDING.md`](MODEL_ONBOARDING.md)，
> 需求边界见 [`TRAIN_EVAL_REQUIREMENTS.md`](TRAIN_EVAL_REQUIREMENTS.md)。

## 0. 架构底座：两纵一脊

仓库整合三类异构模型（单帧检测 / 实时滑窗时序 / 离线全量时序）的训练与评估。落地为
**两纵一脊**：

- **脊柱（`core/`）**：与模型语义无关的通用能力——run 组织、配置、环境、checkpoint 自描述、
  结果三态信封、异构矩阵、完整性检查。**脊柱不 import 任何纵**。
- **两纵（`temporal/` / `detection/`）**：各自完整的流水线实现，**互不 import**，只在 core 的
  信封与矩阵处汇合。
- **组合根（`cli/_registry.py`）**：唯一同时认识两纵的地方，按 `pipeline` 分派。

依赖方向单向指向脊柱，这是下面所有准则的物理基础。

## 1. 抽象的取舍标尺

一句话：**抽象的收益 = 隔离的变化 + 复用的共性 − 引入的认知成本。** 不为优雅买单。

### 1.1 抽象先隔离脆弱点，再谈优雅

判据：**它挡住了哪个方向的变化传播？** 挡不住变化的抽象只是装饰。

- 范例：`temporal/data.py` 的 features 契约（bbox→40 维）把"数据集格式"变化挡在 loader 层，
  pipeline 的训练/评估循环不受冲击。
- 范例：两纵互不 import，temporal 的数据格式改动**物理上**无法波及 detection。

### 1.2 复用只落在共性稳定处

- core（三态信封 / checkpoint 自描述 / RunContext）被两纵**真实共用**才成立。
- 差异点分散、不共线时**不强抽基类**：两条时序 pipeline 的差异在数据集 / loss / 推理三处，刻意
  保持扁平双文件；曾删掉过 `feeding/` 策略层，就是从过度抽象退回来。
- **共性稳定是前提，代码长得像不是。** 未来的新流水线未必只在某一维度上变，不要把"当前恰好
  相似"焊成永久契约。

### 1.3 拒绝两种过度设计

- **死抽象**：零调用点的类（`feature_schema.py::FeatureSchema` 已删——特征兼容检查实际由
  `integrity.check_feature_schema` 的裸 dict 比较承担）。
  **硬线**：抽象至少 1 个真实调用点，承重抽象要 ≥2 个跨消费者。删前先 grep 调用点，零调用即删。
- **漏抽象**：号称通用却编码了某一纵的词汇——`apply_overrides` 曾硬编码 torch 的 `batch_size`，
  对 ultralytics（读 `batch`）静默失效，已改为通用 `-S/--set` 点路径寻址。
  **判据**：审"脊柱 / 通用"层时，找里面有没有某条纵才懂的名词，有 = 泄漏耦合。

### 1.4 模型只管网络，语义归流水线

- 监督口径与推理方式**不写进模型**：全序列逐帧 CE、滑窗末帧 CE + 因果平滑，都由流水线拥有。
- 模型携带自身训练细节走**可选 duck-type 钩子**（`fit_normalization` / `compute_loss`），有则调、
  无则退化，**不为此立基类**。

## 2. 不变量（重构不得破坏）

- **结果三态**：`NOT_APPLICABLE` / `MISSING` / `COMPUTED` 严格区分，禁止用 0 冒充 N/A。
- **checkpoint 不静默加载**：错配立即抛 `CompatibilityError`。
- **推理语义显式**：离线模型绝不产生虚假实时延迟（标 `N/A`）。
- **异构矩阵不综合评分**：允许不同模型不同指标列，不对跨类指标生成统一分数。
- **代码只产事实**：完整性检查只描述"评估是否可解释"，晋升决定由人负责。

## 3. 操作化 checklist

- 删代码前：grep 调用点，零调用即删。
- 抽象前：数差异点是否共线、消费者是否 ≥2、共性是否稳定；否则先不抽。
- 审"通用/脊柱"层：里面有没有某条纵才懂的名词？有 = 泄漏，要么下沉到纵、要么改成中立寻址。
- 改流水线：监督/推理语义是否仍留在流水线、没渗进模型？
