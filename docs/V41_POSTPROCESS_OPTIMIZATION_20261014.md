## 一、参数扫描设计

在双向时长先验（min_len 合并 + max_len 拆分）基础上，扫描三个正交维度：

| 维度 | 范围 | 说明 |
|---|---|---|
| min_len 全局缩放 | 0.5~2.0 × P10 | 当前先验是否过保守/过激进 |
| idle_min 独立调节 | 3~60 帧 | idle 段的合并门槛 |
| 动作类 min 缩放 | 0.2~1.5 × P10 | 动作段合并门槛 |
| 概率平滑窗口 k | 1~11 帧 | 移动平均降低帧级抖动 |

## 二、关键发现：min_len 过保守是根因

### 2.1 基线 vs 最优

| 配置 | min_len | 平滑 k | edit 中位 | edit 均值 | F1@0.25 |
|---|---|---|---:|---:|---:|
| 基线（P10 先验） | [11,3,17,98,44,10] | 1 | 56.25 | 54.90 | 50.00 |
| **最优（动作类 ×0.2）** | **[11,1,3,19,8,2]** | **5** | **69.23** | **65.69** | **52.78** |
| **提升** | | | **+12.98** | **+10.79** | **+2.78** |

### 2.2 为什么 P10 先验过保守

P10 = 该类段长的第 10 百分位。用 P10 作为"低于此长度就该合并"的门槛，
实际上把大量**真实的短动作段**误并为 idle。扫描发现动作类的 min_len 应设为 P10 × 0.2
（即 P2 水平），仅保留"极短的噪声段"才合并。

各维度单独贡献：

| 维度 | 单独最优 | edit 中位 |
|---|---|---:|
| 动作 min ×0.2（idle 不变） | [11,1,3,19,8,2] | ~68 |
| idle_min 不变（11） | — | — |
| 概率平滑 k=5 | — | +1~2 额外 |
| 两者联合 | — | **69.23** |

### 2.3 精细扫描 Top 5（共 100 组合）

|---:|---:|---:|---:|---:|

## 三、idle 惩罚实验（否定结论）

### 3.1 动机

idle 占全部帧的 55.7%，疑虑"当前指标中 idle 贡献占比过大"。

### 3.2 方法

在 argmax 前对 idle 概率乘以惩罚因子（或等价地对非 idle 类乘以 boost）。

### 3.3 结果

| factor（idle×） | edit 中位 | edit 均值 | F1@0.25 | 帧准确率 | **非 idle 帧准确率** |
|---:|---:|---:|---:|---:|---:|
| **1.0（不惩罚）** | **69.23** | **65.69** | **52.78** | **66.0%** | 51.7% |
| 0.9 | 68.42 | 64.49 | 51.35 | 65.9% | 52.1% |
| 0.8 | 64.71 | 62.73 | 50.00 | 65.5% | 51.8% |
| 0.7 | 64.29 | 62.28 | 50.00 | 65.0% | 52.4% |
| 0.5 | 64.29 | 61.32 | 47.22 | 63.7% | 52.7% |
| 0.3 | 61.54 | 59.99 | 46.58 | 61.8% | 53.1% |
| 0.2 | 60.87 | 58.91 | 42.42 | 60.4% | 54.0% |

### 3.4 结论

1. **idle 惩罚是"拆东墙补西墙"**——非 idle 帧准确率确实提升（51.7%→54.0%），但代价是
   idle 段被错误报为动作，整体 edit 反而从 69.23 降至 60.87（**-8.4**）；
2. **模型的 idle 偏好是数据分布的合理反映**（idle 占 55.7%），不是概率校准偏差；
3. **edit 指标本身已对 idle 贡献打了折扣**——段级编辑距离用的是最长公共子序列，
   idle 帧大量正确匹配不会像帧级 accuracy 那样灌水。

> **否定结论记录：idle 概率惩罚不应作为后处理策略。** 此结论适用于 v4.1 口径；
> 若数据分布大幅变化（idle 占比 < 40%），需重新评估。

## 四、最终推荐配置

```python
# 后处理生产配置（v4.1，LOVO 中位 edit 69.23）
MIN_LEN = [11, 1, 3, 19, 8, 2]   # idle, water, flush, lbi, lbw, sbc
MAX_LEN = [288, 3, 89, 232, 92, 131]  # 保持 P95 不变
SMOOTH_K = 5                      # 概率移动平均窗口
IDLE_FACTOR = 1.0                 # 不惩罚
```

处理流程：
1. 概率移动平均（k=5，因果侧可用右侧 padding）
2. argmax 得到逐帧预测
3. min 合并（短于 min_len[c] 的段并入更长的邻居）
4. max 拆分（超过 max_len[c] 的段在 max_len 处截断，余下归邻居类）
