# 手部区域锚点：v1（最大 hand 框）→ v2（全部 hand 框并集）（2026-10-11）

> **本文件是过程文档**（生命周期 ≤ 1 周）；落到长期位置的是两个新契约
> [`actionmixed-bbox-hand-8cls-v2`](../../features/README.md) /
> `actionmixed-bbox-global-hand-8cls-v2`、两条训练配置与
> `tools/probe_hand_region_screen.py`。
>
> **一句话**：把 v4.1 上最强帧准确率驱动——**手部区域特征**——的区域锚点从
> "面积最大的单个 hand 框"改成"**全部 hand 框的并集**"，在 val 与 test 上**同时**改善
> `acc` 与 `edit`，且段级指标达到配对显著（test f1@0.5 **p=0.0006**）。

## 1. 为什么筛这条轴

v4.1 全量重训（22 臂 × 8 seed）的 acc 排名给出很硬的信号：**手部区域段是最强的帧准确率驱动**

| 契约 | 维度 | v4.1 test acc |
|---|---:|---:|
| 全画面 bbox `actionmixed-bbox-8cls-v1` | 40 | 69.38 |
| 仅手部 `actionmixed-bbox-hand-8cls-v1` | 40 | 75.98 |
| 全局+手部 `...-global-hand-8cls-v1` | 80 | **76.27**（全仓库单模型最高） |

而这个 recipe 的两个关键选择**从来没有被调过**（都写死在 `features/hand_bbox.py`）：

1. 锚点 = **面积最大的单个 hand 框** → 左右手都检出时区域只圈住一只，
   器械在两手之间传递时区域会跳；
2. `HAND_REGION_EXPAND = 1.5`。

## 2. 源域筛选（只碰 train，不碰 test）

工具（已入库）：[`tools/probe_hand_region_screen.py`](../../../tools/probe_hand_region_screen.py)
—— auto **train** 28 视频 / 27,092 帧、视频级 10 折留出、HistGB；
Δ = **留出视频逐帧 acc − 该折全 idle 基线**；配对用逐折 Wilcoxon。

| 变体 | 维度 | Δ中位 | 配对 vs v1（1.5 × 最大框） |
|---|---:|---:|---|
| 全局+手部 1.5 × 最大框（**v1 现行**） | 80 | +11.64 | — |
| 全局+手部 1.0 × **并集** | 80 | +12.25 | **+1.83pp，10/0，p=0.002** |
| 全局+手部 1.25 × **并集** | 80 | **+12.78** | **+1.20pp，10/0，p=0.002** |
| 全局+手部 1.5 × 并集 | 80 | +11.60 | +1.20pp，8/2，p=0.193 |
| 全局+手部 2.0 × 并集 | 80 | +12.00 | +1.25pp，8/2，p=0.014 |
| 仅手部 1.0 × 最大框 | 40 | +1.55 | −10.10pp，1/9，p=0.004 |
| 仅手部 1.5 × 最大框（**v1 现行**） | 40 | +6.56 | −4.11pp，1/9，p=0.006 |
| 仅手部 2.0 × **并集** | 40 | +14.65 | +1.86pp，8/2，**p=0.027** |
| 仅手部 3.0 × **并集** | 40 | **+15.08** | **+2.39pp，8/2，p=0.020** |

**读法**：锚点（最大框 → 并集）在两个维度上都带来源域增益，且**同一扩张倍数下对比最干净**
（仅手部 1.5：+6.56 → +13.41）。仅手部 recipe 的扩张倍数在 2.0~4.0 之间已经饱和（10.6~15.1），
故取 **2.0** 作为契约点（留一点余量、避免把最优当默认）。

> 注意筛选的**边界**：变体 ∈ {1.0, 1.25, 1.5, 2.0, 2.5, 3.0, 4.0} × {最大框, 并集}，
> 只覆盖这一族；"更聪明的锚点"（例如按 hand 框面积加权、或对器械框做聚类）未探索。

## 3. mstcn2 训练验证（v2 臂 8 → **16 seed**，与 v4.1 各臂同配方）

两个新契约 + 与父契约逐 (seed, 视频) × 类配对（`tools/compare_runs.py`）。
**v2 臂已扩到 16 seed**（8-seed 的 acc 判读落在 ±0.7~1.3pp 噪声地板内，见
[`../../EVAL.md`](../../EVAL.md) §9.2）；父契约沿用 v4.1 批次的 8 seed（配对检验只用重叠的 8 个 seed）。

| 契约 | 维度 | 锚点/扩张 | seed | val acc | val edit | test acc | test edit | test f1@0.25 | test f1@0.5 |
|---|---:|---|---:|---:|---:|---:|---:|---:|---:|
| `bbox-hand` v1（对照） | 40 | 最大框 / 1.5 | 8 | 68.26 | 75.06 | 75.98 | 62.44 | 57.42 | 44.26 |
| **`bbox-hand` v2** | 40 | **并集 / 2.0** | 16 | 77.75 | 76.36 | **77.75** | **66.35** | 68.53 | 55.36 |
| `bbox-global-hand` v1（对照） | 80 | 最大框 / 1.5 | 8 | 72.36 | 72.29 | 76.27 | 64.14 | 65.10 | 53.80 |
| **`bbox-global-hand` v2** | 80 | **并集 / 1.5** | 16 | 75.17 | 75.14 | **79.15** | **66.37** | **69.86** | **58.88** |
| （参照）`roi-grid-v5`（原 edit 冠军） | 192 | — | 8 | 73.01 | 72.44 | 74.53 | 69.43 | 67.28 | 48.56 |
| （参照）旗舰 `roi-grid-v4` | 128 | — | 8 | 70.24 | 74.55 | 64.91 | 62.64 | 56.56 | 36.30 |

**逐 seed 中位 + 摆幅（16 seed）**：`hand-v2` test acc 77.75（76.31~81.34）/ edit 66.35（60.45~73.45）；
`global-hand-v2` test acc 79.15 / edit 66.37。8 seed 与 16 seed 的中位差仅 −0.05 / −0.64
（acc / edit），读数稳定。

**配对检验（test）**

| 对照 | edit 中位差 (p) | f1@0.1 (p) | f1@0.25 (p) | f1@0.5 (p) |
|---|---|---|---|---|
| `global-hand-v2` − `global-hand-v1`（**只差锚点**） | +7.09 (0.149) | **+5.86 (0.017)** | **+5.77 (0.011)** | **+6.41 (0.0006)** |
| `hand-v2` − `hand-v1`（锚点 + 扩张） | +7.87 (0.051) | +2.39 (0.159) | **+6.33 (0.028)** | **+4.62 (0.028)** |

**逐类帧召回（%）** —— 锚点改动换到了什么，这张表最清楚：

| 契约 | idle | flush | long_brush_insert | long_brush_withdraw | short_brush_cleaning | frame macro_f1 |
|---|---:|---:|---:|---:|---:|---:|
| `bbox-hand` v1 | 80.0 | 68.1 | 83.1 | 57.9 | **0.0** | 58.47 |
| **`bbox-hand` v2** | 83.2 | **70.7** | **86.4** | 65.6 | **0.0** | **73.41** |
| `bbox-global-hand` v1 | 89.2 | 30.1 | 82.0 | 61.1 | 28.3 | 62.83 |
| **`bbox-global-hand` v2** | **90.5** | 52.5 | 80.7 | **67.9** | 28.3 | 67.54 |
| （参照）`roi-grid-v5` | 90.4 | 55.9 | 67.6 | 55.6 | **56.3** | 68.84 |

**结论**：

1. **锚点是一条真杠杆**：只改锚点（80 维契约、其余逐位不变）即拿到
   test **acc 76.27 → 79.15（+2.88）/ edit 64.14 → 66.37（+2.23）**、
   val **acc 72.36 → 75.17（+2.81）/ edit 72.29 → 75.14（+2.85）**，段级 F1 在三个阈值上配对显著
   （p ≤ 0.017）——**本 session 第一条在两个 split、两个指标上同时改善的单模型改动**。
2. **小特征打赢大特征**：40 维 `bbox-hand-v2` 的 **val acc 77.75 是全仓库最高**，
   80 维 `bbox-global-hand-v2` 的 **test acc 79.15 是全仓库最高**；两者都远高于
   192 维 `roi-v5`（val 73.01 / test 74.53）与 128 维旗舰。**"加维度"不是方向**。
3. **机制**：并集区域让左右手同时入镜、器械在手间传递时区域不再跳 → 预测段数比
   **1.10 → 0.95**（少掉多余段）、`fn` 37 → 32、`fp` 32 → 30；召回上最直接的受益者是
   **`flush`（global-hand 30.1 → 52.5；hand 68.1 → 70.7）** 与 **`withdraw`（61.1 → 67.9）**，
   `hand-v2` 还把 `insert` 推到 86.4（全仓库最高）。代价是 `sbc` 仍为 **0**。
4. **仍然缺 `sbc`**：`roi-v5` 是唯一能拿到 `sbc` 56.3 的契约。

### 3.1 把新契约放进投票协议（读已存盘产物，零训练成本）

| 协议 | test acc | test edit | val acc | val edit |
|---|---:|---:|---:|---:|
| `global-hand-v2` 单 seed 中位 | 79.79 | 67.86 | 75.17 | 75.14 |
| `global-hand-v2` 同契约 8-seed 投票 | **80.50** | **71.24** | 76.59 | **77.81** |
| `hand-v2` 单 seed 中位 | 77.70 | 66.01 | 78.30 | 76.59 |
| `hand-v2` 同契约 8-seed 投票 | 78.70 | 67.66 | 79.08 | 76.29 |
| `hand-v2 + roi-v5` 跨契约投票 | 79.17 | **75.93** | 79.35 | 69.36 |

- **同契约投票在新契约上依然成立且更干净**：`global-hand-v2` 的投票在 **test 与 val、acc 与 edit
  四个格子上全部为正**（+0.71/+3.38/+1.41/+2.33）→ 与 round-1 的结论一致，且有新契约支持。
- **跨契约投票的老毛病又出现一次**：`hand-v2 + roi-v5` 在 test 上 edit **+6.50**（补齐了 `sbc`），
  但 val 上 edit **−7.23（仅 1/6 视频为正）** → 第三次复现"test 上的 edit 增益不迁移到 val"
  （前两次见 [`VOTING_AND_COMBO2_20261010.md`](VOTING_AND_COMBO2_20261010.md) §3）。
  **若要补 `sbc`，必须做单模型拼接（`hand-v2 ‖ roi-v5`）并在 val 上验证，而不是靠投票。**

## 4. 复现

```bash
source ../CleanSightBackend/.venv/bin/activate

# ① 源域筛选（几分钟，纯 CPU，不训练）
python tools/probe_hand_region_screen.py --folds 10 --held 6

# ② 两臂训练（8 seed，约 20 min/臂）
bash tmp/v41push/run_hand_v2.sh run            # 已跑：runs/v41-push/feat-{hand,global-hand}-v2/
bash tmp/v41push/run_hand_v2_ext.sh            # 种子扩展 8 → 16（11,13,17,19,23,29,31,37）

# ③ val 侧复评（默认只评 test）+ 配对对照
python tools/eval_runs_on_split.py --split val --workers 3 \
  --run "runs/v41-push/feat-global-hand-v2/h128/*"
python tools/compare_runs.py \
  --left  "runs/v41-push/feat-global-hand-v2/h128/mstcn2-*" --left-label "global-hand-v2(并集)" \
  --right "runs/v41/feat-global-hand/h128/mstcn2-*"        --right-label "global-hand-v1(最大框)" \
  --metrics acc,edit,f1_01,f1_025,f1_05
```

产物：`runs/v41-push/feat-hand-v2/`、`runs/v41-push/feat-global-hand-v2/`（各 8 run + 摘要，
种子扩展后各 16 run）、`tmp/v41push/val_evals/`（val 复评）、`tmp/v41push/hand_screen.out`（筛选原始输出）。

## 5. 遗留

1. **`sbc` 缺口（最高优先）**：hand 系契约恒 0 → 候选 = 单模型拼接 `hand-v2 ‖ roi-v5`（232 维）
   或 `global-hand-v2 ‖ roi-v5`（272 维）。**注意**：跨契约投票这条路已在 val 上被否两次
   （见 §3.1），所以必须走拼接、并做 val 验证。
2. **锚点族的进一步探索**：按 hand 框面积加权、只取"持械手"、对器械框做聚类；
   本轮筛选只覆盖 {最大框, 并集} × {1.0, 1.25, 1.5, 2.0, 2.5, 3.0, 4.0} 这一族。
3. **后处理要重测**：段数比已从 1.10 降到 0.95（不再过分割），round-1 那条"最小时长合并"
   的收益是在 v1 契约上得的，在 v2 上预期变小，需要重跑才知道还值不值得开。
4. **交付口径**：`global-hand-v2`（test acc 79.15 / edit 66.37、16 seed）是否作为
   v4.1 的新旗舰契约进入 registry（CARD / pin.yaml）——需要一次决策
   （现旗舰配置仍是 `roi-v4` 128 维：acc 64.91 / edit 62.64）。
5. **在线轨**：v2 契约尚未在滑窗（因果）轨上测过；离线轨的收益有多少能传到在线轨是未知数
   （round-1 已否定"窗口太短"这条解释，在线轨需要另找杠杆）。
