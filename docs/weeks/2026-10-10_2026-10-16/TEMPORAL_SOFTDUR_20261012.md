# 软时长惩罚 β=0.5：本任务时序侧第一个**可交付**的改进（2026-10-12）

> 分支：`feat/temporal-softdur`。工具：`tools/probe_constrained_decoding.py`（修复回溯 bug 之后）。
> 契约 = `combo-v3`（232 维，当前最佳单模型），16 seed，训练无关、零参数。

## 0. 一句话

把"逐帧 argmax"换成**只加软时长惩罚的 Viterbi**（转移先验 α=0，惩罚 `β·max(0, D_c − d)`，
`D_c` = train 真值段时长的 q0.10，**β=0.5 在 val 上选出**）：**test edit 70.40 → 73.24（+2.84，
p<0.001，14 胜 2 负）**、三个段级 F1 门槛 **+1.85~+3.41（全部 p<0.05）**，而 **acc 与 val edit
的代价统计上不显著**（val edit −0.76，p=0.19）。
**这是本任务里第一个两 split 全非负、且不需要改选点指标的时序改进。**

## 1. 为什么 β 要小：代价曲线是单调的

上一轮我报"强约束/强惩罚下 F1 涨但 `val_edit` 显著变差（p=0.0017）→ 与选点指标冲突，不可采用"，
并把"更小 β 的中间工作点"列为未决。本轮把 β 扫描补齐，**val 上确认代价随 β 单调**：

| β | val edit Δ | p | 胜/负 | val f1@0.1 Δ | val f1@0.25 Δ | val f1@0.5 Δ | val acc Δ |
|---:|---:|---:|:--:|---:|---:|---:|---:|
| 0.25 | −0.75 | 0.159 | 6/10 | **+1.66\*** | **+1.71\*** | **+1.10\*** | −0.00 |
| **0.5** | **−0.76** | **0.193** | **7/9** | **+2.15\*** | **+2.24\*** | **+1.76\*** | +0.02 |
| 1 | −1.42\* | 0.009 | 4/12 | +2.74\* | +3.08\* | +2.47\* | +0.14\* |
| 2 | −2.75\* | 0.009 | 5/11 | +3.00\* | +2.85\* | +3.55\* | +0.21\* |

**关键点**：β ≤ 0.5 时 **edit 代价不再显著**（p=0.16 / 0.19），而 **F1 增益仍然显著**。
所以上一轮"没有中间工作点"的判断**过于悲观**——中间点是存在的，它不在"F1 也涨、edit 也涨"，
而在"**F1 显著涨、edit 代价不显著**"。β=0.5 的 F1 增益优于 0.25 而同为不显著代价 → 取 β=0.5。

## 2. 交付口径：β 在 val 上选，test 上报

| split | β | acc Δ | edit Δ | p | 胜/负 | f1@0.1 Δ | f1@0.25 Δ | f1@0.5 Δ |
|---|---:|---:|---:|---:|:--:|---:|---:|---:|
| val | 0.25 | −0.00 | −0.75 | 0.159 | 6/10 | **+1.66\*** | **+1.71\*** | **+1.10\*** |
| val | **0.5** | +0.02 | −0.76 | 0.193 | 7/9 | **+2.15\*** | **+2.24\*** | **+1.76\*** |
| test | 0.25 | +0.10 | **+1.62\*** | 0.002 | 13/2 | **+2.08\*** | **+2.31\*** | **+2.14\*** |
| test | **0.5** | +0.10 | **+2.92\*** | 0.000 | **14/2** | **+2.82\*** | **+3.10\*** | **+3.08\*** |

绝对值（test，16 seed 中位）：

| 指标 | argmax | soft β=0.5 | Δ |
|---|---:|---:|---:|
| acc | 77.40 | 77.67 | **+0.28** |
| edit | 70.40 | **73.24** | **+2.84** |
| f1@0.1 | 77.08 | **79.73** | **+2.65** |
| f1@0.25 | 71.51 | **74.91** | **+3.41** |
| f1@0.5 | 54.23 | **56.08** | **+1.85** |

（`*` = 配对 Wilcoxon p<0.05，n=16 seed；Δ = soft − argmax，pp。）

### 与现行选点指标的关系（这是它能被采用的原因）

配方的选点指标是 `best_metric = val_edit`。β=0.5 的 **val edit 点估计是 −0.76 但 p=0.19**，
即**未被 val 拒绝**；同时 val 的三个 F1 门槛**显著为正**，test 侧 edit 与 F1 全部显著为正。
所以：

- **段级 F1：两 split 都被支持** → 可交付；
- **edit 增益：仅 test 侧显著，val 侧中性** → 应表述为"**未被 val 否定**"，而不是"val 已确认"。
  这是必须写在读数旁边的口径，避免重演本仓库反复出现的"test 涨就当交付"。

## 3. 配方（可直接落地）

```
解码 = Viterbi，状态 (类 c, 已持续帧数 s)
  转移先验   α = 0（不施加；只加时长代价）
  时长代价   离开类 c 时付 β·max(0, D_c − s)，β = 0.5
  D_c        train 真值段时长的 q0.10（本数据集 ≈5 帧）
  训练无关、零参数、无额外权重；推理成本与现有 Viterbi 同量级
```

参数选择记录：β ∈ {0.25, 0.5, 1, 2} 全表在 val 上跑过（§1），**β=0.5 按"F1 显著为正且 edit
代价不显著"选定**；test 只跑过 0.25 与 0.5 作为一致性核对。**没有用 test 选参。**

## 4. 复现

## 5. 遗留

1. **别的契约上是否成立**：本轮只在 `combo-v3` 上做；`hand-v2` / `global-hand-v2` / `roi-v5`
   未测（`roi-v5` 段数比更高，可能受益更多或更少）。
2. **β 的细扫**：0.5 与 1 之间的 0.6~0.8 未测；若目标是最大化 F1 且不在意 edit，β=2 更好。
3. **在线轨**：本杠杆是离线全序列解码；在线（滑窗因果）口径能否同样受益未测。
4. **`D_c` 的分位数**：本轮固定 q0.10；q0.05/0.20 未扫。
5. 工具侧：修复前该工具所有 D>1 读数不可信（见
   [`TEMPORAL_DECODE_FIX_20261012.md`](TEMPORAL_DECODE_FIX_20261012.md)）。


## 6. 泛化核对（2026-10-12 补）：**F1 效应泛化，可交付性不泛化**

把同一配置（β=0.5，`--no-duration` 的转移先验仍为 α=0）套到另外两个契约：

| 契约 | split | acc Δ | edit Δ | p | 胜/负 | f1@0.1 Δ | f1@0.25 Δ | f1@0.5 Δ |
|---|---|---:|---:|---:|:--:|---:|---:|---:|
| `combo-v3` | val | +0.02 | −0.76 | 0.193 | 7/9 | **+2.15\*** | **+2.24\*** | **+1.76\*** |
| `combo-v3` | test | +0.10 | **+2.92\*** | 0.000 | 14/2 | **+2.82\*** | **+3.10\*** | **+3.08\*** |
| `hand-v2` | val | +0.07 | **−2.32\*** | 0.009 | 4/12 | **+1.39\*** | **+1.36\*** | **+1.54\*** |
| `hand-v2` | test | −0.03 | +1.15 | 0.096 | 10/4 | **+1.85\*** | **+1.73\*** | **+1.52\*** |
| `global-hand-v2` | val | +0.03 | **−3.34\*** | 0.018 | 4/12 | **+2.56\*** | **+3.23\*** | **+2.72\*** |
| `global-hand-v2` | test | +0.03 | **+1.57\*** | 0.044 | 13/3 | **+1.74\*** | **+1.92\*** | **+1.83\*** |

（16 seed 配对 Wilcoxon；Δ = soft β=0.5 − argmax，pp。）

**两条分开的结论**：

1. **F1 效应泛化**：三个契约 × 两个 split × 三个 IoU 门槛 = **18/18 显著为正**，
   增益 +1.36~+3.23pp。这是该杠杆的稳健性质，不是 combo-v3 的偶然。
2. **可交付性不泛化**：`best_metric = val_edit` 口径下，**另外两个契约的 val edit 显著变差**
   （hand-v2 −2.32、p=0.009；global-hand-v2 −3.34、p=0.018 —— 两者都是 4 胜 12 负），
   而 combo-v3 的 val edit 代价只是"不显著"（−0.76、p=0.193）。
   → **combo-v3 是 β=0.5 的有利个案，不是规律。** §0 那句"第一个可交付的改进"**只对
   `combo-v3` 成立**，不能读成"这个解码改动整体可交付"。

**因此下一步不是"推广配置"，而是在每个契约上重新扫 β**（像 combo-v3 那样找"F1 显著为正
且 edit 代价不显著"的 β）。`hand-v2` / `global-hand-v2` 需要的 β 大概率明显小于 0.5
（它们的 val edit 对 β 更敏感）。在此之前，本杠杆的交付范围**限定在 combo-v3**。


## 7. 逐契约扫 β（2026-10-12 补）：**β 必须逐契约选，`hand-v2` 在 β=0.1 上可交付**

§6 的结论是"要逐契约重扫 β"。本轮在 val 上扫小 β，结果**三个契约的最优 β 差 5 倍**：

| 契约 | β=0.1 | β=0.25 | β=0.5 | 采纳点 |
|---|---|---|---|---|
| `hand-v2` val edit Δ (p) | **+0.01 (0.669, 8/8)** | −0.98 (0.083, 6/10) | −2.32\* (0.009, 4/12) | **β=0.1** |
| `global-hand-v2` val edit Δ (p) | −1.77\* (0.013, 3/13) | −2.66\* (0.005, 4/12) | −3.34\* (0.018, 4/12) | **范围内无** |
| `combo-v3` val edit Δ (p) | — | — | −0.76 (0.193, 7/9) | β=0.5（§2） |

（同表各 β 的 f1@0.1/0.25/0.5 在两契约、三个 β 上**全部显著为正**。）

- **`hand-v2`：β=0.1 是本任务目前最干净的一个可交付点**——val 侧 edit 代价**字面为零**
  （+0.01、p=0.669、8 胜 8 负），F1 三个门槛 +0.86/+0.95/+0.59 全部显著。
- **`global-hand-v2`：测试范围内（0.1~0.5）没有一个 β 的 val edit 代价可接受**，
  即便最小的 0.1 也已显著变差（−1.77、p=0.013、3 胜 13 负）→ 该契约要么需要 β<0.1
  （未扫），要么在 `val_edit` 选点口径下**不可采用**。

### `hand-v2` 的交付口径读数（β=0.1 在 val 上选，test 上报，16 seed 配对）

| 指标 | argmax | soft β=0.1 | Δ | p | 胜/负 |
|---|---:|---:|---:|---:|:--:|
| acc | 77.75 | 77.88 | +0.04\* | 0.025 | 9/4 |
| edit | 66.35 | 66.57 | +0.62 | 0.060 | 10/2 |
| f1@0.1 | 73.87 | **75.17** | **+1.02\*** | 0.001 | **13/0** |
| f1@0.25 | 68.53 | **69.97** | **+0.97\*** | 0.001 | **13/0** |
| f1@0.5 | 55.37 | **56.64** | **+0.80\*** | 0.001 | **13/0** |

**两个 split、五个指标全部非负**：val edit +0.01（不显著）、test edit +0.62（不显著、正向）、
acc 微增、F1 三个门槛 test 侧 **13 胜 0 负**。比 `combo-v3` 的 β=0.5 更干净
（后者 val edit 是 −0.76）。

### 更新后的小结（替代 §0 的单点结论）

| 契约 | 可交付 β | 依据 |
|---|---|---|
| `combo-v3` | 0.5 | val edit −0.76 (ns)、test edit +2.92\*、F1 显著 |
| **`hand-v2`** | **0.1** | **val edit +0.01 (ns)、test edit +0.62 (ns)、F1 三门槛 13/0 显著** |
| `global-hand-v2` | 范围内无（需 β<0.1） | 最小 β=0.1 已使 val edit 显著变差 |

**规则**：软时长惩罚的 β **必须逐契约在 val 上选**，契约间最优值可差 5 倍；
F1 增益是普适的，但"代价是否可接受"完全取决于契约（`global-hand-v2` 对 β 最敏感）。


## 8. `global-hand-v2` 补扫 β<0.1（2026-10-12 补）：**修正 §7 的"范围内无"**

§7 只扫到 β=0.1 就判 `global-hand-v2` "范围内无采纳点"，**过头了**。补扫 0.02/0.05 后该契约
同样有可用点：

| β | val edit Δ | p | 胜/负 | val f1@.1/25/5 Δ |
|---:|---:|---:|:--:|---|
| 0.02 | −0.16\* | 0.034 | 4/8 | +0.80\*/+0.66\*/+0.64\* |
| **0.05** | **−0.63** | **0.084** | **4/10** | **+1.33\*/+1.14\*/+1.10\*** |
| 0.1 | −1.77\* | 0.013 | 3/13 | +1.68\*/+1.34\*/+1.32\* |

**采纳点 = β=0.05**（edit 代价不显著，F1 三门槛显著）。交付口径读数（β=0.05 在 val 上选、
test 上报，16 seed 配对）：

| 指标 | argmax | soft β=0.05 | Δ | p | 胜/负 |
|---|---:|---:|---:|---:|:--:|
| acc | 79.14 | 79.08 | +0.02 | 0.183 | 10/3 |
| edit | 66.37 | 67.80 | +0.79 | 0.091 | 9/2 |
| f1@0.1 | 74.61 | **76.61** | **+1.04*** | 0.003 | 11/0 |
| f1@0.25 | 69.86 | **71.18** | **+1.16*** | 0.002 | 12/0 |
| f1@0.5 | 58.88 | **61.07** | **+0.81*** | 0.004 | 10/1 |

### 一条方法学提醒（比结论本身更重要）

注意 β=0.02 与 0.05 的**目测大小与显著性方向相反**：0.02 的点估计更小（−0.16）却
**显著**（p=0.034），0.05 的点估计更大（−0.63）却**不显著**（p=0.084）。
→ 在这个量级（<1pp）上，**"p≥0.05 就采纳"这个闸门本身是脆的**，不宜当作硬判据。
更稳的表述是：**β ∈ [0.02, 0.5] 全区间都能用不到 1pp 的 edit 代价换到 ≥0.6pp 的 F1 增益**，
具体 β 按契约对 edit 的敏感度取（本表三契约分别取 0.5 / 0.1 / 0.05）。

### 更新后的小结（替代 §7 表）

| 契约 | 采纳 β | val edit Δ (p) | test edit Δ (p) | test f1@.25 Δ (p) |
|---|---:|---|---|---|
| `combo-v3` | 0.5 | −0.76 (0.193) | **+2.92\*** (<0.001) | **+3.10\*** |
| `hand-v2` | 0.1 | +0.01 (0.669) | +0.62 (0.060) | **+0.97\*** (0.001) |
| `global-hand-v2` | 0.05 | −0.63 (0.084) | +0.79 (0.091) | **+1.16\*** (0.002) |

**三个契约都有了可用 β**，且都是"val edit 代价不显著 + F1 两 split 显著为正"。

## 9. 第四个契约 `roi-v5`（2026-10-12 补）：方向一致，但**样本不足以立量级**

`roi-v5`（192 维）只有 **8 seed**（`runs/v41/feat-roi-v5/h128/` 全量就 8 个 run），
val 上扫得：

| β | n | edit Δ | p | 胜/负 | f1@0.1 Δ | f1@0.25 Δ | f1@0.5 Δ | acc Δ |
|---:|---:|---:|---:|:--:|---:|---:|---:|---:|
| 0.1 | 8 | -0.23 | 0.844 | 4/4 | +1.00* | +0.57* | +0.31* | +0.02 |
| 0.5 | 8 | -1.46 | 0.109 | 3/5 | +1.64* | +2.02* | +0.58 | -0.09 |

**结论要收着说**：方向与另外三个契约**一致**（F1 正、edit 代价不显著），但
**只有 8 seed**，而本项目自己的纪律是「判 <1.5pp 的差异必须 ≥16 seed」
（见周简报 §3 已知限制）——上表的 F1 增益只有 +0.31~+2.02，**大部分落在噪声地板以下**。
因此：

- `roi-v5` 只能记为「**方向一致、未被否定**」，**不能**列为第四个可交付点；
- 要把它变成结论，需先补齐 seed 数（该 run 目录只有 8 个训练产物）或换用同一 seed 集重训。

至此四个契约的覆盖情况：`combo-v3`(16 seed) / `hand-v2`(16) / `global-hand-v2`(16) 三个有
可交付 β；`roi-v5`(8 seed) 方向一致但样本不足。


## 10. 落地计划：把软时长惩罚从探针提到推理链路（2026-10-12 摸底，**尚未实施**）

§0–§7 已把这条增益验证清楚（3 个契约各有可用 β，16 seed 配对、两 split 显著为正），
但它**目前只在 `tools/probe_constrained_decoding.py`（探针）里**——探针只读产物、不改推理，
**所以这条增益现在不可部署**。本节把落地位置查清楚。

### 10.1 改动点（已按源码定位）

| 位置 | 现状 | 要改什么 |
|---|---|---|
| `framework/cleansight_eval/temporal/full_sequence_pipeline.py` **L147 / L181** | 两处 `torch.argmax(logits[0], dim=-1)`——现行离线解码（零平滑） | 换成带软时长惩罚的 Viterbi 解码；两处都要改，否则 `predict` 与 `evaluate` 口径会分叉 |
| `framework/cleansight_eval/core/config.py` **L89**（`evaluation` 允许键集合）、**L111–114**（默认值） | 已有 `smoothing_min_duration`（在线侧用） | 加 `duration_soft_strength`（β）与 `duration_quantile`（默认 0.10） |
| `framework/cleansight_eval/temporal/sliding_window_pipeline.py` **L62 / L434 / L464** | 在线侧用 `causal_decision(min_duration=25)` | **本计划不动在线侧**（在线已有 §10 之外的那条门槛杠杆） |

### 10.2 唯一需要设计决策的地方：`D_c` 从哪来

软惩罚的强度是 `β·max(0, D_c − d)`，而 `D_c` = **train 真值**段时长的 q0.10 分位。
探针在读产物时顺手 `load_split(train)` 就能算，但**推理链路里没有 train 标签**。两条路：

- **(a) 评测时现算**：在 pipeline 里额外加载 train split 的标签估 `D_c`。
  改动小，但给推理引入"训练集必须就在那儿"的依赖 —— **部署时不可接受**（交付环境不该带 train 标签）。
- **(b) 训练时算好、写进 checkpoint meta**（**推荐**）：`D_c` 是**训练集的属性**，
  与权重同为模型产物的一部分，理应随 checkpoint 落盘；推理只读 meta。
  这样解码器自洽、可部署，且 `D_c` 与权重版本天然绑定（换数据换权重时它自动跟着变）。

**建议取 (b)**，并在 `pin.yaml` 里登记 `duration_quantile` 与 `D_c`（按 skill 的注册表要求：
改变特征映射/阈值属新版本，需可复现）。

### 10.3 验收判据（照探针里已经用过的那些）

1. **β=0 必须逐帧等价于现行 argmax**——这是判别性断言（探针里 `tests/test_probe_constrained_decoding.py`
   已有一条同型用例，且已做过对抗性复核：还原 bug 后该用例会红）。**落地时必须先过这条**，
   否则等于在未察觉的情况下改了全部历史读数。
2. 在 `combo-v3` / `hand-v2` / `global-hand-v2` 三个契约上，用**同一 seed 集**复现 §2/§7 的 β 增益
   （val 选 β、test 上报），且 `acc` 与 `edit` 的配对结论与探针一致。
3. 落盘 meta 后跑一次"换机器/无 train 标签"的评测，确认解码仍可用（验证 (b) 的部署性）。

### 10.4 为什么本轮不做

改动跨 3 个文件 + 需要动 checkpoint meta 的 schema（属中等改动），且本机 GPU 正被 YOLO 全量训练
占用、我的工作余量也不足以稳妥完成。**故本轮只把位置、决策与验收判据查清写定**，
交给余量充足时执行——避免在"赶"的状态下动推理链路（那会影响**所有**历史读数）。


## 11. 接线形状已查定（2026-10-12，**仍未接线**）：改动比预想小，只剩 `D_c` 的来源

§10 只定位了"改哪两处"，本轮把**两处的上下文读完**，接线形状因此确定。两处的 logits 形状
与调用方式完全一样：

```python
# framework/cleansight_eval/temporal/full_sequence_pipeline.py
# 站点 1：_infer_split()          L146-147
logits = model(x)                     # [1, T, C]
preds.append(torch.argmax(logits[0], dim=-1).cpu().numpy().astype(np.int64))
# 站点 2：_evaluate_full_sequence() L180-181（同一形状；该函数同时还算 loss，替换只动预测那行）
```

⇒ 接线 = **加一个解码 helper + 两处替换**，helper 的入参已经齐备：

```python
def _decode(logits_1tc, min_duration, soft_strength):      # logits: [1, T, C]
    if soft_strength <= 0:                                  # 默认等价现行 argmax
        return torch.argmax(logits_1tc[0], dim=-1).cpu().numpy().astype(np.int64)
    return viterbi_decode(logits_1tc[0].cpu().numpy(),
                          np.zeros((C, C)),                 # α=0 ⇒ 转移先验不参与
                          min_duration, transition_strength=0.0,
                          hard_duration=False, soft_duration_strength=soft_strength)
```

三点已确认，**不再是未知数**：

1. **转移先验不用传真值**：验证过的配置是 **α=0**（只用时长代价），故
   `np.zeros((C, C))` 即可——探针当时也是这么调的，**不需要为它读 train**。
2. **两个站点可以共用一个 helper**，`predict` 与 `evaluate` 口径不会分叉（§10.1 担心的那点）。
3. **默认路径保持逐帧 argmax**（`soft_strength <= 0` 直接走原分支），因此**接线本身不改任何
   历史读数**；这也让"β=0 必须等于 argmax"这条验收判据在实现层面天然成立，并由
   `framework/tests/test_soft_duration_decoding.py` 的判别性用例兜住。

### 于是**唯一**剩下的实质工作就是 `D_c` 的来源

- 短期（评测可用）：在 pipeline 初始化时对 **train** split 调
  `estimate_min_duration(train_truths, C, quantile)`——该仓库的评测流程本就持有 train 数据；
- 目标形态（部署可用）：**训练时算好写进 checkpoint meta**，推理只读 meta（§10.2 的推荐），
  并在 `pin.yaml` 登记 `duration_quantile` 与 `D_c`。

**建议**：先用"评测时现算"把 β 增益在**真实评测链路**上复现一遍（这是"不可部署"到"可验证"
的关键一步），确认与探针结论一致后，再补 meta 落盘。两步分开做，避免一次性改动既动行为
又动 schema。


## 12. 接线范围已核实（2026-10-12 补）：两个调用点都拿得到 `cfg`，改动确实小

§11 写的"一个 helper + 两处替换"当时是**照着函数体推的**，没核对调用点。本轮把调用点查清，
结论**成立**，并把当时没验的那一环补上：

| 解码函数 | 调用点 | 所在函数 | `cfg` 是否在手边 |
|---|---|---|---|
| `_infer_split(model, features, device)` | L530 | `predict(self, cfg, ckpt, device)`（L517） | **是** |
| `_evaluate_full_sequence(model, features, truths, id2name, criterion, device)` | L458 | `train(self, cfg, runs_dir, seed, device)`（L267） | **是** |

⇒ 两个函数各加一个可选参数（解码设置），在调用点从 `cfg["evaluation"]` 取并传入即可，
**不需要改别处的签名或调用链**。这也顺带满足了 §10.1 那条"两处都要改、否则 predict 与
evaluate 口径分叉"的要求——两处可以共用同一份解码设置。

### 仍未解决、且**无法靠读代码绕过**的一环：`D_c` 的来源

- `predict(self, cfg, ckpt, device)` 只拿到特征与 checkpoint，**手里没有 train 标签**
  ⇒ 想在那里自动估 `D_c` 是不可行的；
- 故要完整接线，`D_c` 必须**持久化**（config 显式给出，或随 checkpoint meta 落盘）。

**因此建议的落地顺序（两小步，各自可验证）**：

1. **先做"显式配置"版**：`cfg["evaluation"]` 增加 `duration_soft_strength`（β）与
   `duration_min_frames`（`D_c` 列表，缺省则 β 视为 0），helper 只读配置。
   这一步能立刻在**真实评测链路**上复现 β 增益（用探针算出的 `D_c` 填进去即可），
   且默认不改变任何行为；
2. **再做"自动 + 持久化"版**：训练时用 train 真值估 `D_c`、写进 checkpoint meta，
   推理只读 meta（§10.2 的推荐形态），并在 `pin.yaml` 登记 `duration_quantile` 与 `D_c`。

这样第 1 步就已经让这条增益**可验证、可在评测链路里复现**（从"不可部署"变成"可验证"），
而不必等第 2 步的 schema 改动。

## 14. 失败归因的下一步调查（2026-10-12）：形状是异质的，别再假设 `[1,T,C]`

§13 的失败（`preds` 里出现 0 维数组）需要先弄清"解码点拿到的到底是什么形状"。本轮做了
**源码侧的形状普查**（只读，未改动任何代码），结果说明**不能再假设所有模型都返回 `[1,T,C]`**：

| 模型文件 | 返回形状线索 |
|---|---|
| `mstcn.py` | L90 `return logits.transpose(1, 2)  # [B, T, C]` |
| `clean_offline.py` | L122 `return logits.transpose(1, 2)` |
| `actionness.py` | L160 `return compose_log_probability(actionness, class_logits).transpose(1, 2)`；另有独立的 `compute_loss`（L162） |
| `fact.py` | L213 `return self._token_mixture_logits(token_logits, token_time)`（**经 token 混合**，非朴素转置） |
| `boxset.py` / `gru.py` / `transformer.py` | 各有自己的 `forward`/`compute_loss` 组合 |

即：**各 head 的"前向返回值"语义并不统一**——有的返回转置后的 logits、有的经 token 混合、
有的同时提供 `compute_loss`。而 §13 那次改动只在**合成张量**上验过 `[1,T,C]`，所以
"某条真实路径产出 0 维数组"是完全可能的（例如某 head 返回 `[T,C]` 或 `[1,C]` 一类形状，
使 `logits[0]` 之后 argmax 得到标量）。

### 下一次尝试的修正方案（把鲁棒性写进 helper，而不是假设形状）

1. **helper 里显式规范化形状**：接受 `[1,T,C]`、`[T,C]`、`[B,T,C]`，统一到 `[T,C]` 后再解码；
   形状无法归一就**抛错并打印实际形状**（而不是静默产出 0 维数组）；
2. **先跑真实模型的形状探针**：对 MS-TCN / MS-TCN++ / Transformer / actionness / fact
   各跑一次前向，**打印** `type(ret)` 与 `ret.shape`，再动手接线；
3. **把 `test_mstcn_smoke.py` 两条用例作为接线的门槛**——它们正是 §13 抓到回归的那两条，
   比任何合成用例都贴近真实。

**当前结论：接线仍未完成**，前置调查（第 2 条）尚未做；仓库处于接线前状态（§13 已回退并核实）。


## 15. 形状探针：**§14 的假设被自己的实测推翻**（2026-10-12）

§14 从源码 `return logits.transpose(1, 2)` 一类线索推断"各 head 返回形状异质，可能导致 0 维
数组"。本轮**直接跑了形状探针**（逐 `model.type` 构造、前向 `[1,20,40]`、打印返回 type 与 shape；
只读、不改仓库）：

```

_build_asformer                -> Tensor shape=(1, 20, 6)
_build_clean_asformer          -> Tensor shape=(1, 20, 6)
_build_clean_bigru             -> Tensor shape=(1, 20, 6)
_build_clean_mstcn_bilstm      -> Tensor shape=(1, 20, 6)
```

**结论：13 个 builder 里能构造的 12 个，前向返回一律是 `[1, T, C]`**——`[1,T,C]` 这个假设
**本来就是对的**。所以 §14 关于"形状异质导致 0 维数组"的推断**被推翻**，§13 那个
`TypeError: iteration over a 0-d array` **另有原因，目前仍未定位**。

### 为什么这次自我推翻值得记下来

§14 是**从源码的 `return ... .transpose(1, 2)` 反推**出来的，读起来很合理（转置确实存在），
但**转置之后仍是 `[B,T,C]`**——我只看到"有 transpose"就推出了"形状不统一"，
中间少了一步验证。**又一次"没量就下结论"，只是这次错在归因而不在数字。**
教训：**形状、取值域这类可一次测出的事实，一律先测再写**；源码里的模式（transpose、reshape）
不能替代实测形状。
