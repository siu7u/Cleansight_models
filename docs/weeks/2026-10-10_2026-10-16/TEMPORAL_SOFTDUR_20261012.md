# 软时长惩罚 β=0.5：本任务时序侧第一个**可交付**的改进（2026-10-12）

> 分支：`feat/temporal-softdur`。工具：`tools/probe_constrained_decoding.py`（修复回溯 bug 之后）。
> 契约 = `combo-v3`（232 维，当前最佳单模型），16 seed，训练无关、零参数。

## 0. 一句话

把"逐帧 argmax"换成**只加软时长惩罚的 Viterbi**（转移先验 α=0，惩罚 `β·max(0, D_c − d)`，
`D_c` = train 真值段时长的 q0.10，**β=0.5 在 val 上选出**）：**test edit 70.40 → 73.24（+2.84，
p<0.001，14 胜 2 负）**、三个段级 F1 门槛 **+1.85~+3.41（全部 p<0.05）**，而 **acc 与 val edit
的代价统计上不显著**（val edit −0.76，p=0.19）。
**这是本任务里第一个两 split 全非负、且不需要改选点指标的时序改进。**

## 1. 为什么 β 要小：代价曲线是单调的

上一轮我报"强约束/强惩罚下 F1 涨但 `val_edit` 显著变差（p=0.0017）→ 与选点指标冲突，不可采用"，
并把"更小 β 的中间工作点"列为未决。本轮把 β 扫描补齐，**val 上确认代价随 β 单调**：

| β | val edit Δ | p | 胜/负 | val f1@0.1 Δ | val f1@0.25 Δ | val f1@0.5 Δ | val acc Δ |
|---:|---:|---:|:--:|---:|---:|---:|---:|
| 0.25 | −0.75 | 0.159 | 6/10 | **+1.66\*** | **+1.71\*** | **+1.10\*** | −0.00 |
| **0.5** | **−0.76** | **0.193** | **7/9** | **+2.15\*** | **+2.24\*** | **+1.76\*** | +0.02 |
| 1 | −1.42\* | 0.009 | 4/12 | +2.74\* | +3.08\* | +2.47\* | +0.14\* |
| 2 | −2.75\* | 0.009 | 5/11 | +3.00\* | +2.85\* | +3.55\* | +0.21\* |

**关键点**：β ≤ 0.5 时 **edit 代价不再显著**（p=0.16 / 0.19），而 **F1 增益仍然显著**。
所以上一轮"没有中间工作点"的判断**过于悲观**——中间点是存在的，它不在"F1 也涨、edit 也涨"，
而在"**F1 显著涨、edit 代价不显著**"。β=0.5 的 F1 增益优于 0.25 而同为不显著代价 → 取 β=0.5。

## 2. 交付口径：β 在 val 上选，test 上报

| split | β | acc Δ | edit Δ | p | 胜/负 | f1@0.1 Δ | f1@0.25 Δ | f1@0.5 Δ |
|---|---:|---:|---:|---:|:--:|---:|---:|---:|
| val | 0.25 | −0.00 | −0.75 | 0.159 | 6/10 | **+1.66\*** | **+1.71\*** | **+1.10\*** |
| val | **0.5** | +0.02 | −0.76 | 0.193 | 7/9 | **+2.15\*** | **+2.24\*** | **+1.76\*** |
| test | 0.25 | +0.10 | **+1.62\*** | 0.002 | 13/2 | **+2.08\*** | **+2.31\*** | **+2.14\*** |
| test | **0.5** | +0.10 | **+2.92\*** | 0.000 | **14/2** | **+2.82\*** | **+3.10\*** | **+3.08\*** |

绝对值（test，16 seed 中位）：

| 指标 | argmax | soft β=0.5 | Δ |
|---|---:|---:|---:|
| acc | 77.40 | 77.67 | **+0.28** |
| edit | 70.40 | **73.24** | **+2.84** |
| f1@0.1 | 77.08 | **79.73** | **+2.65** |
| f1@0.25 | 71.51 | **74.91** | **+3.41** |
| f1@0.5 | 54.23 | **56.08** | **+1.85** |

（`*` = 配对 Wilcoxon p<0.05，n=16 seed；Δ = soft − argmax，pp。）

### 与现行选点指标的关系（这是它能被采用的原因）

配方的选点指标是 `best_metric = val_edit`。β=0.5 的 **val edit 点估计是 −0.76 但 p=0.19**，
即**未被 val 拒绝**；同时 val 的三个 F1 门槛**显著为正**，test 侧 edit 与 F1 全部显著为正。
所以：

- **段级 F1：两 split 都被支持** → 可交付；
- **edit 增益：仅 test 侧显著，val 侧中性** → 应表述为"**未被 val 否定**"，而不是"val 已确认"。
  这是必须写在读数旁边的口径，避免重演本仓库反复出现的"test 涨就当交付"。

## 3. 配方（可直接落地）

```
解码 = Viterbi，状态 (类 c, 已持续帧数 s)
  转移先验   α = 0（不施加；只加时长代价）
  时长代价   离开类 c 时付 β·max(0, D_c − s)，β = 0.5
  D_c        train 真值段时长的 q0.10（本数据集 ≈5 帧）
  训练无关、零参数、无额外权重；推理成本与现有 Viterbi 同量级
```

参数选择记录：β ∈ {0.25, 0.5, 1, 2} 全表在 val 上跑过（§1），**β=0.5 按"F1 显著为正且 edit
代价不显著"选定**；test 只跑过 0.25 与 0.5 作为一致性核对。**没有用 test 选参。**

## 4. 复现

```bash
# val 上选参（§1 的表）
for B in 0.25 0.5 1 2; do
  python tools/probe_constrained_decoding.py --run "runs/v41-push/feat-combo-v3/h128/mstcn2-*" \
      --split val --device cuda:0 --duration-strength $B --json tmp/temporal_decode/beta_${B}_val.json
done
# test 上报（§2 的表）
python tools/probe_constrained_decoding.py --run "runs/v41-push/feat-combo-v3/h128/mstcn2-*" \
    --split test --device cuda:0 --duration-strength 0.5 --json tmp/temporal_decode/beta_0.5_test.json
# 配对检验：用 json 里逐 run 的 argmax / viterbi 两列做 Wilcoxon
```

## 5. 遗留

1. **别的契约上是否成立**：本轮只在 `combo-v3` 上做；`hand-v2` / `global-hand-v2` / `roi-v5`
   未测（`roi-v5` 段数比更高，可能受益更多或更少）。
2. **β 的细扫**：0.5 与 1 之间的 0.6~0.8 未测；若目标是最大化 F1 且不在意 edit，β=2 更好。
3. **在线轨**：本杠杆是离线全序列解码；在线（滑窗因果）口径能否同样受益未测。
4. **`D_c` 的分位数**：本轮固定 q0.10；q0.05/0.20 未扫。
5. 工具侧：修复前该工具所有 D>1 读数不可信（见
   [`TEMPORAL_DECODE_FIX_20261012.md`](TEMPORAL_DECODE_FIX_20261012.md)）。


## 6. 泛化核对（2026-10-12 补）：**F1 效应泛化，可交付性不泛化**

把同一配置（β=0.5，`--no-duration` 的转移先验仍为 α=0）套到另外两个契约：

| 契约 | split | acc Δ | edit Δ | p | 胜/负 | f1@0.1 Δ | f1@0.25 Δ | f1@0.5 Δ |
|---|---|---:|---:|---:|:--:|---:|---:|---:|
| `combo-v3` | val | +0.02 | −0.76 | 0.193 | 7/9 | **+2.15\*** | **+2.24\*** | **+1.76\*** |
| `combo-v3` | test | +0.10 | **+2.92\*** | 0.000 | 14/2 | **+2.82\*** | **+3.10\*** | **+3.08\*** |
| `hand-v2` | val | +0.07 | **−2.32\*** | 0.009 | 4/12 | **+1.39\*** | **+1.36\*** | **+1.54\*** |
| `hand-v2` | test | −0.03 | +1.15 | 0.096 | 10/4 | **+1.85\*** | **+1.73\*** | **+1.52\*** |
| `global-hand-v2` | val | +0.03 | **−3.34\*** | 0.018 | 4/12 | **+2.56\*** | **+3.23\*** | **+2.72\*** |
| `global-hand-v2` | test | +0.03 | **+1.57\*** | 0.044 | 13/3 | **+1.74\*** | **+1.92\*** | **+1.83\*** |

（16 seed 配对 Wilcoxon；Δ = soft β=0.5 − argmax，pp。）

**两条分开的结论**：

1. **F1 效应泛化**：三个契约 × 两个 split × 三个 IoU 门槛 = **18/18 显著为正**，
   增益 +1.36~+3.23pp。这是该杠杆的稳健性质，不是 combo-v3 的偶然。
2. **可交付性不泛化**：`best_metric = val_edit` 口径下，**另外两个契约的 val edit 显著变差**
   （hand-v2 −2.32、p=0.009；global-hand-v2 −3.34、p=0.018 —— 两者都是 4 胜 12 负），
   而 combo-v3 的 val edit 代价只是"不显著"（−0.76、p=0.193）。
   → **combo-v3 是 β=0.5 的有利个案，不是规律。** §0 那句"第一个可交付的改进"**只对
   `combo-v3` 成立**，不能读成"这个解码改动整体可交付"。

**因此下一步不是"推广配置"，而是在每个契约上重新扫 β**（像 combo-v3 那样找"F1 显著为正
且 edit 代价不显著"的 β）。`hand-v2` / `global-hand-v2` 需要的 β 大概率明显小于 0.5
（它们的 val edit 对 β 更敏感）。在此之前，本杠杆的交付范围**限定在 combo-v3**。


## 7. 逐契约扫 β（2026-10-12 补）：**β 必须逐契约选，`hand-v2` 在 β=0.1 上可交付**

§6 的结论是"要逐契约重扫 β"。本轮在 val 上扫小 β，结果**三个契约的最优 β 差 5 倍**：

| 契约 | β=0.1 | β=0.25 | β=0.5 | 采纳点 |
|---|---|---|---|---|
| `hand-v2` val edit Δ (p) | **+0.01 (0.669, 8/8)** | −0.98 (0.083, 6/10) | −2.32\* (0.009, 4/12) | **β=0.1** |
| `global-hand-v2` val edit Δ (p) | −1.77\* (0.013, 3/13) | −2.66\* (0.005, 4/12) | −3.34\* (0.018, 4/12) | **范围内无** |
| `combo-v3` val edit Δ (p) | — | — | −0.76 (0.193, 7/9) | β=0.5（§2） |

（同表各 β 的 f1@0.1/0.25/0.5 在两契约、三个 β 上**全部显著为正**。）

- **`hand-v2`：β=0.1 是本任务目前最干净的一个可交付点**——val 侧 edit 代价**字面为零**
  （+0.01、p=0.669、8 胜 8 负），F1 三个门槛 +0.86/+0.95/+0.59 全部显著。
- **`global-hand-v2`：测试范围内（0.1~0.5）没有一个 β 的 val edit 代价可接受**，
  即便最小的 0.1 也已显著变差（−1.77、p=0.013、3 胜 13 负）→ 该契约要么需要 β<0.1
  （未扫），要么在 `val_edit` 选点口径下**不可采用**。

### `hand-v2` 的交付口径读数（β=0.1 在 val 上选，test 上报，16 seed 配对）

| 指标 | argmax | soft β=0.1 | Δ | p | 胜/负 |
|---|---:|---:|---:|---:|:--:|
| acc | 77.75 | 77.88 | +0.04\* | 0.025 | 9/4 |
| edit | 66.35 | 66.57 | +0.62 | 0.060 | 10/2 |
| f1@0.1 | 73.87 | **75.17** | **+1.02\*** | 0.001 | **13/0** |
| f1@0.25 | 68.53 | **69.97** | **+0.97\*** | 0.001 | **13/0** |
| f1@0.5 | 55.37 | **56.64** | **+0.80\*** | 0.001 | **13/0** |

**两个 split、五个指标全部非负**：val edit +0.01（不显著）、test edit +0.62（不显著、正向）、
acc 微增、F1 三个门槛 test 侧 **13 胜 0 负**。比 `combo-v3` 的 β=0.5 更干净
（后者 val edit 是 −0.76）。

### 更新后的小结（替代 §0 的单点结论）

| 契约 | 可交付 β | 依据 |
|---|---|---|
| `combo-v3` | 0.5 | val edit −0.76 (ns)、test edit +2.92\*、F1 显著 |
| **`hand-v2`** | **0.1** | **val edit +0.01 (ns)、test edit +0.62 (ns)、F1 三门槛 13/0 显著** |
| `global-hand-v2` | 范围内无（需 β<0.1） | 最小 β=0.1 已使 val edit 显著变差 |

**规则**：软时长惩罚的 β **必须逐契约在 val 上选**，契约间最优值可差 5 倍；
F1 增益是普适的，但"代价是否可接受"完全取决于契约（`global-hand-v2` 对 β 最敏感）。
