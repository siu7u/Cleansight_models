# 约束感知解码在 combo-v3 上重测：转移先验是真杠杆，硬时长约束是毒药（2026-10-12）

> 过程性文档，属本周（2026-10-10 ~ 10-16）。分支：`feat/temporal-decode`。
> 用现成工具 `tools/probe_constrained_decoding.py`（**训练无关、零参数**），
> 只读既有 checkpoint 与产物，不训练、不改模型。契约 = `combo-v3`（232 维，当前最佳单模型）。

## 0. 一句话结论

把"逐帧 argmax"换成**带转移先验的 Viterbi**（不加时长约束），在 **16 seed 配对**下：
**段级 F1 三个 IoU 门槛在 val 与 test 上全部显著为正（18/18）**，且增益随先验权重 α 单调增
（test `f1@0.25`：+0.47 → +1.27 → **+1.69**）；但 **`edit` 在 val 上随 α 单调变差**
（−0.14 → −0.99\* → −1.80\*），test 上只有不显著的小幅正值。
**在 `edit` 作为选点指标的现行口径下不可采用**；它是"以 edit 换段质量"的取舍，不是免费增益。

而工具默认的**硬时长约束**（类最短时长 = train 段时长 q0.10）在 combo-v3 上**灾难性失败**：
16/16 run 变差、段数比塌到 0.04、几乎全判 idle。**两个组件的方向相反**，必须分开说。

## 1. 硬时长约束：0/16，直接否决

工具默认口径（转移权重 α=0.0 + 类最短时长硬约束 q0.10）：

| split | 解码 | acc | edit | f1@0.1 | f1@0.25 | f1@0.5 | 段数比 | 段覆盖率中位 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| val | argmax | 77.91 | 75.78 | 67.47 | 62.90 | 43.62 | 1.05 | 70.1% |
| val | viterbi | 58.36 | **5.70** | 6.94 | 2.31 | 0.00 | **0.04** | **0.0%** |
| test | argmax | 77.40 | 70.40 | 77.08 | 71.51 | 54.23 | 0.99 | 75.6% |
| test | viterbi | 41.18 | **13.27** | 16.47 | 7.06 | 0.00 | **0.10** | **0.0%** |

逐 run edit 提升 **0/16**（两侧都是），逐类召回除 idle 外全塌到 0。

**为什么**：该约束是为**旧旗舰**（`roi-grid-144`，真值段内非 idle 帧比例中位数仅 1.4%）设计的
——那时模型几乎不出段，硬逼它"段至少持续 N 帧"是净收益。而 combo-v3 的段覆盖率中位已经到
**75.6%**（argmax），这个病灶**已经被锚点 v2 / 拼接修复了**；此时"每类至少 N 帧"的硬约束只剩
副作用：模型对非 idle 帧的置信度本就不高，Viterbi 在"多停 N 帧"与"回 idle"之间会一致选 idle
→ 整条序列塌成 idle。**工具要修的是个已经不存在的问题。**

## 2. 转移先验（去掉硬时长约束）：段级 F1 稳定为正，edit 是取舍

`--no-duration --transition-strength α`，16 seed 配对 Wilcoxon（`*` = p<0.05）：

| α | split | edit Δ | p | f1@0.1 Δ | p | f1@0.25 Δ | p | f1@0.5 Δ | p |
|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.25 | val | −0.14 | 0.156 | **+0.90\*** | 0.008 | **+0.96\*** | 0.002 | **+0.99\*** | 0.001 |
| 0.25 | test | +0.72 | 0.064 | **+0.61\*** | 0.003 | **+0.47\*** | 0.003 | **+0.48\*** | 0.023 |
| 0.5 | val | **−0.99\*** | 0.039 | **+1.13\*** | 0.017 | **+1.54\*** | 0.003 | **+1.17\*** | 0.001 |
| 0.5 | test | +0.21 | 0.281 | **+0.84\*** | 0.003 | **+1.27\*** | 0.004 | **+0.43\*** | 0.023 |
| 1.0 | val | **−1.80\*** | 0.016 | **+1.65\*** | 0.006 | **+2.03\*** | 0.000 | **+1.58\*** | 0.000 |
| 1.0 | test | +0.57 | 0.348 | **+1.59\*** | 0.000 | **+1.69\*** | 0.000 | **+1.32\*** | 0.002 |

`acc` 在 α=0.5 上是 val +0.05（p=0.10）/ test +0.02（p=0.16）——**不变**。

### 读法

1. **段质量（F1 家族）是真增益且稳健**：三个 α × 两个 split × 三个 IoU 门槛 = **18/18 显著为正**，
   胜/负比一致偏向正（如 α=1.0 test f1@0.25：12 胜 3 负）。增益随 α 单调增，说明信号方向稳定，
   α=0.5 不是运气。
2. **`edit` 与之反向且随 α 恶化**：val 上从 −0.14(不显著) 一路到 **−1.80\*（显著）**；
   test 上始终只有不显著的正值。这是"多切/少切"的经典取舍：Viterbi 的转移先验压低类间抖动、
   把段做得更"实"，于是严格 IoU 下匹配更多（F1 涨），但段序列与真值的编辑距离在真值段边界
   敏感的场景里反而变差。
3. **与现行选点口径冲突**：`mstcn2` 配方是 `best_metric = val_edit`，而本杠杆**恰好让 val edit 变差**。
   所以在不改选点指标的前提下，它**不可采用**——这是一个需要在"交付指标是什么"这一层做的决策，
   不是可以直接落地的解码替换。
4. **α 必须在 val 上选**：按 F1 选最优是 α=1.0，按 edit 选是 α=0。本次三个 α 的两侧结果都列出，
   正是为了让"选哪个 α"这件事不悄悄变成 test 选参。

## 3. 复现命令

```bash
# 1) 工具默认口径（含硬时长约束）——用于确认它在本契约上是灾难
python tools/probe_constrained_decoding.py \
    --run "runs/v41-push/feat-combo-v3/h128/mstcn2-*" --split test --device cuda:0

# 2) 只留转移先验（本文主结果）；把 α 换成 0.25 / 0.5 / 1.0 各跑一遍
for S in val test; do
  python tools/probe_constrained_decoding.py \
      --run "runs/v41-push/feat-combo-v3/h128/mstcn2-*" --split $S --device cuda:0 \
      --no-duration --transition-strength 1.0 --json tmp/temporal_decode/combo_v3_${S}.json
done
# 3) 配对检验（16 seed Wilcoxon）用上面 --json 里的逐 run argmax / viterbi 两列直接算
```

**注意**：`--device` 要 torch 形式（`cuda:0`），传 `0` 会 `RuntimeError: Invalid device string`。

## 4. 遗留

1. **要不要为段质量改选点指标**：若交付更看段级 F1（而非 edit），则 α=1.0 + Viterbi 是
   现成的、零训练的 +1.59/+1.69/+1.32（test，均显著）；若坚持 edit 选点，则本杠杆不能用。
2. **α 的 val 选参**：本文只扫了 {0.25, 0.5, 1.0}；若决定采用，需按交付指标在 val 上正式选一次。
3. **结构性解码仍未试**：起止集合约束（本工具未实现）与"非 idle 段最短时长**软**约束"
   （硬约束已证有害）是两个方向；后者可能是唯一能同时要 F1 与 edit 的形态。
4. 本工具在**其他契约**（`hand-v2` / `global-hand-v2` / `roi-v5`）上未测——段数比越低的契约
   越可能从转移先验里受益。
