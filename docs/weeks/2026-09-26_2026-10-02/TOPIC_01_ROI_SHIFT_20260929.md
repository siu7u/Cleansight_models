# 课题①：ROI 测试数据是否存在镜像 / 空间偏移

> 脚本：`tmp/acc-decomp/roi_shift.py`（可复现运行，双重证据）
> 数据：`datasets/cleansight-ActionMixed-auto-lhh`，test 8 视频 / 2639 帧
> 模型：`runs/acc-push/acc-roiv4/h128/mstcn2-*`（8 seed，v4 契约）
> **结论：否定镜像假设，也否定系统性取景偏移假设；但得到一个关键机制线索——水平(x)分箱是承重结构。**

## 1. 为什么必须查这一条

test 来自 Label Studio `project-18`（2026-09「长短毛刷」专场），train/val 来自 `project-16`（2026-08）。
两批次若**画面朝向或取景中心不同**（镜头左右颠倒、器械出现在画面另一侧），那么
`roi-grid-v4` 的"左上/右下"格子语义在 test 上就**对不上**——模型会系统性失准，
而且**看起来像模型问题、实际是数据侧的空间错位**。

这类问题与第 7 轮查过的「时间轴偏移」是同一类错误（错的是坐标轴不同），
一旦成立，后续所有特征工程的结论都要重估，所以必须先排除。

## 2. 证据 1：动作帧的 3×3 区域占用率（弱工具）

在**真值非 idle 帧**上，统计高频 3 类在 3×3 网格里的平均占用率向量，比较
"train vs test"、"train vs test 水平镜像"、"train vs test 垂直镜像" 的相关系数：

| 类 | corr(train,test) | vs 水平镜像 | vs 垂直镜像 | 表面判读 |
|---|---:|---:|---:|---|
| hand | **+0.957** | +0.980 | +0.529 | 水平镜像"更像" |
| scope_control_body | +0.489 | +0.497 | **+0.977** | 垂直镜像"更像" |
| scope_mid_section | +0.879 | +0.879 | +0.886 | 三者在噪声内 |

**这条证据单独不可用**：三类给出三种互相矛盾的"更像"，说明相关系数在此是**弱工具**
——占用率矩阵结构性很强（多数格子非零、量级相近），三种假设的读数都被抬到高相关区，
差值落在噪声里。原始行边际也提示更像"整体下移一行"而非真镜像（例：scope_control_body
行边际 train [0.032, 0.166, 0.127] vs test [0.185, 0.183, 0.022]），
但**边际差异同样可能来自两批次的操作习惯差异**，不能据此判定错位。

## 3. 证据 2：决定性检验（把已训练模型跑在变换后的 test 特征上）

做法：对 8 个**已训练**的 v4 模型，把 test 特征做空间变换后重跑，看哪一版的读数更高。
若 test 相对 train 真的镜像/偏移了，那么"把它变换回去"的那一版应当**显著更高**。

| 变换 | 中位 acc | Δ 中位 |
|---|---:|---:|
| 原样 | 57.60 | +0.00 |
| 水平镜像 | 54.64 | **−2.96** |
| 垂直镜像 | 54.45 | **−3.15** |
| 重分箱 y+0.10（下移） | 56.78 | −0.81 |
| 重分箱 y−0.10（上移） | 56.35 | −1.25 |
| 重分箱 y+0.20（下移两格） | 55.15 | −2.44 |
| 重分箱 y−0.20（上移两格） | 55.67 | −1.93 |
| 重分箱 x+0.10 | 51.99 | **−5.61** |
| 重分箱 x−0.10 | 50.55 | **−7.05** |

**判读**：所有变换都**更差**，没有任何一版能超过原样 → **镜像与取景偏移假设均被否定**。
正确朝向本身就是一个约 3pp 的判别信号（翻转即掉 3pp），说明模型确实在用方向语义，
而不是对方向不敏感。

### 附带产出：x 承重、y 宽容

同样的 ±0.10 重分箱，**x 方向掉 5.61~7.05pp，y 方向只掉 0.81~1.25pp**——差 5~7 倍。
这说明 3×3 网格里**列（水平）划分承担了绝大部分判别信息，行（垂直）划分相当宽容**。
与本轮课题④/⑦ 的机制解释互相印证：器械的"左右"位置（术者手侧 vs 镜体侧 vs 器械盘侧）
比"上下"位置更能区分动作；把维度预算继续投在行划分上收益有限，
而 col 划分或"列上的亚格位置（dx）"更值得投（第 6/7 轮的 v4→v5 筛选也指向同一方向，
但 v5 在 8-seed 端到端上 57.05 < v4 57.59，说明该方向的信息增益被维度预算吃掉了）。

## 4. 一次方法学事故（保留记录）

本脚本第一版把 6 个偏移变体的 test 特征**拍平成"逐帧列表"**返回，
而 `evaluate()` 用 `zip(逐视频特征, 逐视频标签)` 配对，于是变成了"1 帧 vs 整段标签"，
广播后读数**恰好落在平凡全 idle 基线 55.25**——6 个变体 × 8 seed 全部是 55.25。
数值过于整齐是唯一线索；逐元素核对（自建特征与 `load_split` 输出 `np.array_equal` 为 True）
才定位到是**配对结构**被破坏，而不是特征错了。

**教训**：读数出现"多组配置给出完全相同的异常整齐值"时，优先怀疑**数据结构/配对**，
不要先怀疑超参；且"自建特征 == 真实特征"这一步核对必须做，它能一刀把嫌疑范围切成两半。

## 5. 结论与后续动作

1. **ROI 空间语义在 train/test 之间是一致的**：不需要为空间错位做任何补偿，
   也不应把 test 上不去归因于"画面被翻转/取景不同"。
2. **不要做网格翻转类数据增强**：翻转掉 3pp 说明它破坏语义；把已知错误的变换做增强
   等于把假设空间做错（该判断已写入 `framework/experiments/mstcn2-auto-roi-v4-aug-*.yaml` 的抬头注释）。
3. **维度预算的新线索**：列划分承重、行划分宽容 → 若要继续挤帧级精度，
   优先在**列方向**做更细划分或补列内位置量，而不是继续加行。
4. 与第 7 轮的"时间轴对齐审计（阴性）"合起来看：**空间轴与时间轴都没有发现批次错位**，
   剩下的批次差异属于**分布差异**（尺度、节奏、类别先验），这正是课题②数据增强要处理的。
