## 1. 本轮做了什么（一屏全景）

两条线并行：**攻关线**（12 轮针对 `acc` 的定标实验）+ **课题线**（11 项专题核查）。

| 线 | 规模 | 产出 |
|---|---|---|
| 攻关线 | 12 轮，`runs/acc-push/` 累计 **45 个批次 / 510 个 run** | 1 个有效杠杆 + 16 条轴排除清单 |
| 课题线 | 11 项（镜像偏移、数据增强、数据/原理解释、架构、检测可信度、ROI 理论、指标可信度、fold、离线模型） | 8 份专题文档（共 2140 行）+ 5 个新分析脚本 |
| 工程线 | 训练期增强两项、实验 YAML 3 个、测试 10 项、配置 schema 与文档登记 | 全部缺省逐位等同历史行为，测试全绿 |

**本轮定标结果**（test split，同协议、同架构、同划分）：基线 **53.90 → 58.31**，

参考系：平凡"全 idle"常数预测器 **55.25**（基线低于它，v4 明显高于它）。

## 2. 有效的那一刀：特征契约（唯一产生净增益的方向）

**做法**：不改模型、不改数据，只改"每帧喂给模型的数字怎么排"。两步，都是单变量对照。

### 2.1 第一步 v1 → v2：维度预算重分配（+2.56pp，8/8 胜，p=0.0078）

v1 是 8 个检测类**一律** 2×3 网格（6 区域）× 3 通道 = 每类 18 维，共 144 维。
问题是预算分得"平均"：5 个稀有器械类的框只有人工标注的 **5%~21%**，
也就是 **144 维里约 90 维长年恒零**；而 3 个高频类（hand / scope_control_body /
scope_mid_section，帧出现率 **95.2% / 91.4% / 69.8%**）拿一样的预算。

改法：高频 3 类升到 **3×3**（每类 27 维），低频 5 类压成**全局 1 区域**（每类 3 维）→ **96 维**。
低频类不删——它们在关键动作上有 4~10× 富集（syringe ↔ water_injection、short_brush ↔ sbc），
散在 6 格里几乎恒零，合并成全局通道反而更稠密、更抗漏检。

同轮外推：**v3（高频 4×4，159 维）→ 49.30（−4.62pp）**，说明甜点在 3×3：
更细的分辨率买到的是维度，不是新信息（每帧非空槽位恒约 3 个）。

### 2.2 第二步 v2 → v4：通道语义替换（→57.59 / 32 seed 58.31）

体检发现 v2 的 `presence` 通道**完全冗余**：`presence ≡ count>0`（非空槽平均框数恒 ≈1.05，
`count` 本就退化成 0/1），2 通道与 3 通道的逐折 Δ **30/30 折逐位相同**。
也就是说**每格的有效信息只有 2 个数**，第三、四个槽位本该放新信息。

改法：布局**完全不动**，只把通道 `[presence, count, max_area]` 换成 **`[count, max_area, w, h]`**
→ **128 维**。理由是 `max_area = w×h` 把框压成标量、**丢掉了长宽比**，
而器械形状有判别力（细长内镜 vs 方正刷子）——量出来 `scope_control_body` 的长宽比
类间离散度 **1.12**、面积只有 **0.53**。

**选型纪律**（这条比结果更重要）：v4 是**只看源域筛选表**定下来的，**没有看 test**。
源域协议 = auto train 14 视频、视频级留出折、HistGB、逐折配对；11 种通道组合里
`count,max_area,w,h` 的配对优势 +0.82pp（8/2，p=0.084）。第 12 轮又做了
**布局 × 通道的 30 折联合筛选**（17 个候选），无候选胜出（分辨力 ≤0.1~0.4pp）。

### 2.3 落地链路（每个新契约都走完整条）

新版本模块（`features/roi_bbox_v4.py`）→ `features/__init__.py` 注册**显式块宽**
（v4 高频块 36 维、低频块 4 维，按"总维÷类数"推导会**静默遮错列**）→
`framework/testsets.yaml` 新增 dataset + 三个 split 登记（`tools/validate_testsets.py` 须 ok）→
单元测试 → `docs/features/README.md` 与 `usage/YAML_CONFIG.md` 登记 → 8 seed 定方向 →
**32 seed 严格定标**。

## 3. 这一轮钉死的三件事

### 3.1 天花板位置（可信度证据）

- **噪声地板**：8-seed 中位噪声 **±0.7~1.3pp**；判 <1.5pp 的差异需 ≥16 seed，判 <0.5pp 需 ≥32 seed。
  本轮所有"有效/无效"结论都按这个门限走。
- **划分稳健性**：源域视频级 **30/30 折** v4 都最优；目标批次**留一视频**配对 Δ 区间
  **[+2.85, +5.75]pp**，任何单个留出下都显著为正。
- **下限参照**：平凡全 idle = **55.25**；不做时序的检测框级分类器只到 **53.16~55.25**（6/24/128 维三档），**打不过平凡基线**——时序上下文是唯一有效环节。

### 3.2 钱不该花在哪（排除清单，一屏收掉）

| 轴 | 最好结果 |
|---|---|
| 时序架构 | 8 类旧架构 + 本轮 5 族（asformer / transformer / fact / mstcn+bilstm / mstcn）**全部不如 `mstcn2`**，差 4.5~6.8pp |
| 数据增强 | 旧目标遮罩未过验收；本轮三项新增强 **+0.13 / −0.73 / −2.20pp**（jitter 中性、tscale 有害、叠加更差） |
| 解码 / 校准 / 集成 | 解码 ≤ +1.5pp；val 拟合偏置 **−3.01pp**；集成分歧大且 val 不支持 |
| 跨 seed 权重平均 | **坍缩到 55.25（= 平凡基线）** |
| 正则 / 容量 / 轮数 / 学习率调度 | ≤ +0.6pp；加参数无用；32 seed 下调度无差异（17/15，p=0.81） |
| 标签平滑 | **−0.84pp（10/22，p=0.0035）** |
| 并入更多数据（手动数据集 16 视频） | **−6.17pp 负迁移** |
| 学习式表示（集合编码器） | **−7.84pp（0/8）** |
| 检测侧修复 | 见 §3.3：**能修的检测项与能涨分的检测项不重合** |
| 镜像 / 取景偏移补偿 | **否定**：9 个空间变换全部比原样更差（水平镜像 −2.96、垂直 −3.15pp） |

### 3.3 下一步只能往哪走（机制侧的新线索）

- **检测不是瓶颈**：test 上"动作帧一个框都没有"= **0 帧**、0 框帧 0.08%、逐帧框数 3.59（train 3.46）。
  8 个检测类里只有 `hand`(−2.41) 与 `scope_control_body`(−1.12) 有可辨贡献，
  其余 6 类 |Δ| ≤ 0.21pp；**砍掉冷 5 类反而 +0.57pp**。
- **ROI 网格不是"按格承载"**：宽度匹配的随机 36 维对照把三个热类的消融读数全覆盖
  → "砍掉某个类 = 砍掉任意 36 维热区维度"，代价不可分辨。
  但**方向是对的**：x 承重 / y 宽容（±0.10 重分箱：x 掉 5.61~7.05pp、y 只掉 0.81~1.25pp）。
- **唯一还开着的口子**：`count` 通道**推理期置零反而 +1.21pp**（超出等宽随机块对照的 95 分位），
  `max_area` −2.96pp（真实承重）。即"补信息、换掉退化通道"是唯一有正向证据的方向
  （与既有待办"特征补 Δ 项"重合）。

## 4. 结论的限定条件（这轮量出来的技术事实）

技术同事之间必须讲清的四条，**它们不是"没做好"，而是结论的适用边界**：

1. **增益是帧级 `acc` 专属**：同批 24 对 seed 上，`edit` **−7.93pp（6/18，p=0.0018）**、
   `f1@0.25` 持平（+1.21，ns）。严格可加分解显示 `edit` 的下降**全部来自"段报少了"**
   （段数不匹配 −7.87pp、序列错配 **+2.36pp** 即反而更好）：段数比 0.884 → 0.747，
   v4 有 **19.3%** 的 (run×帧) 整段弃权（v1 仅 5.2%），而 test 的 **164 帧 flush 全落在
   两个"几乎全弃权"的视频里** → flush 召回 0.00% 有了实测解释。
   **下游若消费段级事件，选型要按段级口径重估。**
2. **增益分布不均**：约 **40% 集中在一个视频**（去掉最强 1/2/3 个后残余 +2.85 / +2.52 / +1.86pp）。
   引用增益时应报区间，不报单点。
3. **主语是 `mstcn2`**：同一份 v4 契约喂给单阶段 `mstcn` 只有 54.13（配对 −3.94pp，0/15）
   → **契约收益补偿不了架构差距**，特征与架构不是可分离的两笔账。
4. **流式未验证**：全部结论建立在整段、非因果的 `full_sequence_temporal` 上；
   因果滑窗（GRU）路径**没有任何实测**。

**最可能被问的 6 个问题与答法**

1. *"为什么不用全栈绝对值 59.30？"* → 那是另一套推理协议（集成/选点/后处理）下的读数，
   其同协议基线是 **54.83**；两个协议不能混着比，所以主报 like-for-like。
2. *"涨的是不是只是变保守、少说话？"* → 已用决策率扫描否证：v1 的整个 idle 偏置阈值族最高只到
   54.83，全区间被 v4 压制 +3.3~+4.5pp。误差预算显示 +4.5pp 里 70.6% 来自少误报 idle、
   29.4% 来自多命中动作。
3. *"检测质量是不是拖后腿？"* → 不是：test 动作帧无框 = 0 帧；6 个类边际贡献 |Δ| ≤ 0.21pp。
4. *"加数据不行吗？"* → 并入手动数据集实测 **−6.17pp 负迁移**（形态不同），不是量的问题而是分布问题。
5. *"换个大模型呢？"* → 容量轴已试（h32~h256 无用），架构轴 13 族无一胜出；数据量（14 个训练视频）
   支撑不起更大模型。
6. *"结论能复现吗？"* → 每个数字都有 run 目录 + seed 集合 + 复现命令；脚本在 `tmp/acc-decomp/`，
   报告在 `docs/weeks/2026-09-26_2026-10-02/`。
