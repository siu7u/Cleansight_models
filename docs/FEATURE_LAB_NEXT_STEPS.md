## 3. 准确率低的原因分析（按证据强度分层）

### 3.1 数据层（主因）

1. **训练量严重不足**：14 视频 / 9575 帧。loss 曲线直接证明——val_loss 在 epoch 2~5 见底
   回升（FEATURE_LAB §6.2.1），模型几个 epoch 就记住了训练集，泛化无从谈起；
2. **类别极度失衡**：idle 占 train 65.52% / val 68.20%；water_injection 仅 194 / 17 帧
   （0.50%）——稀有类在交叉熵下被忽略，全零命中是必然；
3. **val 集只有 4 个视频**：单视频分布偏移即可主导指标（seed 间 edit ±7 波动的根源），
   当前数字的置信区间本身就很宽；
4. **特征源头质量**：特征全部来自 YOLO 自动检测框，检测误差原样传导；auto 通道只覆盖
   6 个检测类（**short_brush / brush_tip_out 恒为零**，这两个类等于"看不见"）；标注五列
   无真实置信度（默认 1.0 填充，exploratory 口径）；
5. **动作边界标注模糊**：插入/撤出是渐变过程，人工边界本身有分歧；7.5fps 采样下
   短动作仅剩几帧。

### 3.2 特征层

6. **纯几何丢外观**：器械是否接触镜面、水流是否可见等判别性视觉线索不在 bbox 里；
   S2 的 ImageNet CNN 失败只说明**通用**外观特征不行，不代表外观信息本身没用
   （域内微调是另一回事）；
7. **关键帧特征缺失**：scope 类在手部区域 presence 仅 14~16%（遮挡/出画），
   动作发生瞬间的特征可能正好缺失。

### 3.3 模型层

8. ~~滑窗上下文太短~~ **已被窗口实验证伪（2026-09-22）**：window 16→32→64 在
   test 上 edit 单调变差（25.72→23.48→21.98），val 无增益——加长上下文不解决问题；
   MS-TCN 双向的优势来自**架构（能看未来帧 + 多尺度）**而非窗口长度；
   模型侧的正确方向是因果长程建模或段级结构，而非加大 window；
9. **帧级独立监督**：末帧监督 + 无段级结构约束（无 HMM/CRF 式平滑），帧级抖动直接
   传导到段边界——评估中 start_mae 高达 343 帧即段起点定位差的直接体现。

### 3.4 一句话归因

**主因是数据（量少 + 失衡 + val 太小），次因是时序建模（无段级结构、缺因果长程建模——窗口短已被 §3.3-8 证伪），
特征方案已接近"纯几何"的上限**——v3 相对 bbox-40 的 +12.5 edit 就是特征侧的改进空间；
要从 31 冲到 60+，大概率需要数据与模型侧发力。
