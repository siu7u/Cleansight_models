## 3. 准确率低的原因分析（按证据强度分层）

### 3.1 数据层（主因）

1. **训练量严重不足**：14 视频 / 9575 帧。loss 曲线直接证明——val_loss 在 epoch 2~5 见底
   回升（FEATURE_LAB §6.2.1），模型几个 epoch 就记住了训练集，泛化无从谈起；
2. **类别极度失衡**：idle 占 train 65.52% / val 68.20%；water_injection 仅 194 / 17 帧
   （0.50%）——稀有类在交叉熵下被忽略，全零命中是必然；
3. **val 集只有 4 个视频**：单视频分布偏移即可主导指标（seed 间 edit ±7 波动的根源），
   当前数字的置信区间本身就很宽；
4. **特征源头质量**：特征全部来自 YOLO 自动检测框，检测误差原样传导；auto 通道只覆盖
   6 个检测类（**short_brush / brush_tip_out 恒为零**，这两个类等于"看不见"）；标注五列
   无真实置信度（默认 1.0 填充，exploratory 口径）；
5. **动作边界标注模糊**：插入/撤出是渐变过程，人工边界本身有分歧；7.5fps 采样下
   短动作仅剩几帧。

### 3.2 特征层

6. **纯几何丢外观**：器械是否接触镜面、水流是否可见等判别性视觉线索不在 bbox 里；
   S2 的 ImageNet CNN 失败只说明**通用**外观特征不行，不代表外观信息本身没用
   （域内微调是另一回事）；
7. **关键帧特征缺失**：scope 类在手部区域 presence 仅 14~16%（遮挡/出画），
   动作发生瞬间的特征可能正好缺失。

### 3.3 模型层

8. ~~滑窗上下文太短~~ **已被窗口实验证伪（2026-09-22）**：window 16→32→64 在
   test 上 edit 单调变差（25.72→23.48→21.98），val 无增益——加长上下文不解决问题；
   MS-TCN 双向的优势来自**架构（能看未来帧 + 多尺度）**而非窗口长度；
   模型侧的正确方向是因果长程建模或段级结构，而非加大 window；
9. **帧级独立监督**：末帧监督 + 无段级结构约束（无 HMM/CRF 式平滑），帧级抖动直接
   传导到段边界——评估中 start_mae 高达 343 帧即段起点定位差的直接体现。

### 3.4 一句话归因

**主因是数据（量少 + 失衡 + val 太小），次因是时序建模（无段级结构、缺因果长程建模——窗口短已被 §3.3-8 证伪），
特征方案已接近"纯几何"的上限**——v3 相对 bbox-40 的 +12.5 edit 就是特征侧的改进空间；
要从 31 冲到 60+，大概率需要数据与模型侧发力。

### 3.5 对应的改进方向

| 层 | 方向 | 对应上文 |
|---|---|---|
| 数据 | 采集 action-test 专项数据、补稀有类、扩 val（LOVO 已证实视频难度差异是最大方差源） | §1.3、§3.1、§1.1-#3 |
| 特征 | ~~v3⊕roi 拼接互补~~（已证伪，§1.1-#2）、剔废弃通道（nodep 已定版候选，§2）、域内微调 CNN | §3.2 |
| 模型 | 因果长程建模 / 膨胀卷积 / 段级平滑后处理（~~加长 window~~ 已证伪，§3.3-8） | §3.3 |
| 评估 | ~~LOVO 交叉验证~~（已完成，§1.1-#3）；细化边界指标口径（F1@0.5 薄弱） | §1.1-#3 |

## 4. 组会反馈登记（2026-09-23）：四个重点问题

> 来自组会讨论的四个临床表现问题，逐条对照现有实验证据给出初步归因与建议动作。
> 处置原则：先判数据侧 / 标签侧 / 模型侧，避免直接跳模型改动。

### 4.1 遮挡 / 动作大半出画时识别很差

- **现有证据**：scope 类在手部区域 presence 仅 14~16%（遮挡/出画），动作发生瞬间的特征可能正好缺失（§3.2-7）；v3/v4 已有“缺失龄”通道，但缺失期间模型只能靠回退锚点；LOVO 最难折（fold12 edit 12.0，极差 12.0~71.9，§9）与检测源质量归因一致。
- **初步归因**：**检测/数据侧为主**——bbox 源头看不见，几何特征无从谈起。
- **建议动作**：① 采集含遮挡/出画片段的专项数据（与 §1.3 action-test 专项合并排期）；② 评估 YOLO 对 scope 类在遮挡帧的召回（结合 docs/YOLO_OPTIMIZATION.md 优化线）；③ 模型侧可试 ROI 网格特征在遮挡子集上的稳健性对照（网格统计对单点检测失败更不敏感），但注意 §7.2 已证 roi 被几何特征支配，仅在遮挡子集对比才有意义。

### 4.2 long_brush_withdraw 识别率不高，易混为 long_brush_insert

- **现有证据**：withdraw 是当前最严重的 P0 混淆对（§1.3）；nodep 后 withdraw F1 0.295 为全方案最好（vs v2⊕v3 0.216），但仍低（§8.5）；insert/withdraw 是渐变过程，人工边界本身有分歧，7.5fps 下短动作仅剩几帧（§3.1-5）；长短毛刷专项数据**未采集**（§1.3）。
- **初步归因**：**数据侧为主 + 边界模糊次之**。逐类证据表明剔废弃通道已带来最大单点增益。
- **建议动作**：① 优先落实 §1.3 长短毛刷专项采集（insert/withdraw 正反例都扩）；② 模型侧因果长程建模（§3.3-8 修正后的方向）有望利用“插入在前、拔出在后”的段序先验；③ 评估时关注逐类 F1 与边界指标（docs/assets/feature-lab/fig2_analysis.png ⑥），而非只看段级 edit。

### 4.3 增加动作长短意识（flush 应短暂；是否加时长维度）——**后处理路线已验证（09-27，见 FEATURE_LAB §11）**

- **现有证据**：当前特征只有 3 维时间块（无时长计数）；帧级独立监督、无段级约束（§3.3-9）；flush 在 val 仅 17 帧、六方案全零命中（§1.3）——**flush 的首要问题是数据，不是时长建模**。
- **初步归因**：数据侧（flush 样本太少）优先；“时长意识”作为次级增强方向。
- **建议动作**：① 若引入“当前段已持续帧数”等时长特征，属于**特征映射版本变更**（226 维 → 新版本），按仓库纪律需重训全部时序模型并重新登记契约——成本先评估；② 更轻量的替代：段级后处理加类先验时长约束（如 flush 最短/最长帧数的 HMM 式过滤），不动特征契约；③ 先补 flush 数据再谈建模。
- **结果（09-27）**：路线②已验证——P10 最短段长合并使 LOVO edit 中位 **39.36→48.91（+9.6）**、F1@0.25 **+12.6**，最难折 +44/+48（FEATURE_LAB §11）；特征侧时长意识（路线①）暂缓。剩余工作：因果版实现 + 固定 split 对照 + 条件启用策略。

**TODO（09-27 复盘后新增）：最长段长过滤（修异常长段）——与最短段长互补的另一半**

> 来源：组会反馈复盘（观察：flush 应总是短且多次出现，连续长段 flush 即异常）。
> 数据验证（18 视频 GT / LOVO 预测）：该失败模式**真实存在但频率低于碎段**——
> 预测中 >60 帧的异常长段：sb_cleaning **7 段**（最长 149 帧 vs GT P50=8）、flush 3 段
> （86/74/109 帧）、lb_withdraw 1 段（94 帧，**超 GT 全部历史 max=48**）。
>
> 同时确认现有最短段长过滤的两个缺陷（§11 双刃剑的具体机制）：
> ① 短真段被吃——flush GT 最短 4 帧为真，min_len=7 会误并；
> ② 合并方向偏大类——并入更长邻居≈并入 idle，系统性消灭短动作类。
>
> 实施要点：
> - 规则形态：超类 P95/max 的连续段**拆分或重判**（而非合并），优先针对 sb_cleaning /
>   flush / lb_withdraw；
> - 与最短过滤**组成双向时长先验**，并加短类保护（对 GT 分布本身很短的类跳过合并）；
> - 先验从 GT 拟合——**当前 GT 标注不规范**（idle 有 1 帧噪声段、flush 自带 252 帧异常段、
>   water_injection 全集仅 3 段且双峰），时长先验的可靠性受标注质量制约；
> - **依赖：等待训练集重标完成后重拟合先验再实现/评测**（标注规范修订由标注负责人自行进行）。

### 4.4 搬动内镜被误判为长毛刷刷洗

- **现有证据**：当前 6 类标签空间（idle/water_injection/flush/long_brush_insert/long_brush_withdraw/short_brush_cleaning）**没有“搬动内镜”类**——该状态大概率被标为 idle 或未标注，模型把它归入最近的刷洗类是标签空间缺失的必然结果。
- **初步归因**：**标签侧缺口**，不是模型错误。
- **建议动作**：① 与标注负责人确认“搬动内镜”在现有标注中的归属（标注规范问题）；② 若确认常见且重要 → 扩充类别（需重标 + 重训 + 契约版本升级，成本高）或至少采集专项负样本增强 idle 判别；③ 短期缓解：在模型卡/使用说明层面明示该已知误判模式。
